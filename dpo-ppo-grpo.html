DPO, PPO & GRPO: Three Ways to Align an LLM Without Breaking It

After pre-training on trillions of web tokens and running Supervised Fine-Tuning (SFT) on clean demonstrations, a language model knows how to sound like an assistant. What SFT cannot do is teach the model what not to say, or let it discover a better chain of reasoning than the human annotator wrote down. SFT only clones positive examples token by token; it never compares a good answer against a subtle hallucination or runs live trial-and-error against a test suite.

That gap is where post-training reinforcement learning comes in, and almost every modern alignment pipeline boils down to three algorithms: PPO (Proximal Policy Optimization), DPO (Direct Preference Optimization), and GRPO (Group Relative Policy Optimization).

All three share the exact same goal: push up the probability of high-scoring responses while anchoring the trained policy $\pi_\theta$ close to a frozen reference model $\pi_{\text{ref}}$ so the model doesn't degenerate into gibberish. Where they differ is how much GPU memory they burn and whether the model learns from live on-policy rollouts or static offline preference pairs.

1. PPO: Online Trial-and-Error With Four Models in Memory

Classic RLHF treats alignment like a game. First, you train a separate Reward Model $R_\phi(x, y)$ on human preference pairs to output a scalar score for any prompt $x$ and response $y$. Then you let your active policy $\pi_\theta$ generate live answers and update its weights to maximize that reward.

If you optimize $R_\phi(x, y)$ alone, the LLM quickly discovers reward hacking: it finds weird token loops or sycophantic catchphrases that trick $R_\phi$ into outputting huge scores while reading like nonsense to a human. To prevent that, PPO subtracts a KL-divergence penalty weighted by $\beta$ whenever $\pi_\theta$ drifts away from the frozen SFT reference policy $\pi_{\text{ref}}$, and clips each token's probability ratio $r_t(\theta) = \frac{\pi_\theta(y_t \mid x, y_{<t})}{\pi_{\text{old}}(y_t \mid x, y_{<t})}$ inside $[1 - \epsilon,\; 1 + \epsilon]$ so no single gradient step can blow up the network:

$$\mathcal{J}_{\text{PPO}}(\theta) = \mathbb{E}_t\Bigl[\min\bigl(r_t(\theta) A_t,\; \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) A_t\bigr)\Bigr] - \beta\, D_{\text{KL}}(\pi_\theta \,\|\, \pi_{\text{ref}})$$

Here is the catch: to know whether a reward of $+8$ on a prompt is actually good or bad, PPO needs a per-token baseline expectation $V_\psi(s_t)$ so it can compute the centered Advantage $A_t$. That baseline comes from a trainable Value Critic $V_\psi$—typically another full-sized Transformer. Holding four models in GPU memory at once (trainable Actor $\pi_\theta$, trainable Critic $V_\psi$, frozen Reference $\pi_{\text{ref}}$, and frozen Reward Model $R_\phi$) makes PPO notoriously heavy to run at 70B+ scale.

In a PPO step with clip threshold $\epsilon = 0.20$, a token with positive advantage $A_t = +4$ has old probability $\pi_{\text{old}} = 0.20$ and current probability $\pi_\theta = 0.30$. What is the ratio $r_t(\theta)$, and what does the clipped objective output?

2. DPO: Turning the Policy Into Its Own Reward Model

In 2023, Rafael Rafailov and colleagues noticed a mathematical shortcut hidden inside the KL-constrained reward objective. If you write down the exact closed-form equation for the optimal policy $\pi^*$ that maximizes $R(x, y) - \beta D_{\text{KL}}(\pi \,\|\, \pi_{\text{ref}})$ and solve it for the reward $R(x, y)$, you find that any policy $\pi_\theta$ defines its own implicit reward $\hat{r}_\theta(x, y)$ via the log-ratio against the reference model:

$$\hat{r}_\theta(x, y) = \beta \ln \frac{\pi_\theta(y \mid x)}{\pi_{\text{ref}}(y \mid x)}$$

Why does this matter? Because when humans label a preference pair with a winning response $y_w$ and a losing response $y_l$, the Bradley-Terry preference model says the probability that $y_w$ beats $y_l$ depends only on the difference between their rewards: $\sigma\bigl(\hat{r}_\theta(x, y_w) - \hat{r}_\theta(x, y_l)\bigr)$.

DPO (Direct Preference Optimization) plugs $\hat{r}_\theta$ straight into a binary cross-entropy loss over offline $(x, y_w, y_l)$ pairs:

$$\mathcal{L}_{\text{DPO}}(\theta) = -\ln \sigma\!\left(\beta \ln \frac{\pi_\theta(y_w \mid x)}{\pi_{\text{ref}}(y_w \mid x)} \;-\; \beta \ln \frac{\pi_\theta(y_l \mid x)}{\pi_{\text{ref}}(y_l \mid x)}\right)$$

In one stroke, DPO deletes both the separate Reward Model $R_\phi$ and the Value Critic $V_\psi$, and removes the slow autoregressive generation loop during training. You only keep two models in memory (trainable $\pi_\theta$ and frozen $\pi_{\text{ref}}$) and train with standard supervised forward passes.

Worked Example (DPO Implicit Reward Margin with Base-2 Mental Math):

Use $\log_2$ with $\beta = 1$. For prompt $x$, the frozen reference model assigns probability $\pi_{\text{ref}}(y_w \mid x) = \frac{1}{8}$ to the winner and $\pi_{\text{ref}}(y_l \mid x) = \frac{1}{4}$ to the loser.
After a few updates, our policy assigns $\pi_\theta(y_w \mid x) = \frac{1}{2}$ and $\pi_\theta(y_l \mid x) = \frac{1}{8}$:
1. Winner implicit reward $\hat{r}(y_w)$: $\log_2\!\left(\frac{1/2}{1/8}\right) = \log_2(4) = \mathbf{+2}$.
2. Loser implicit reward $\hat{r}(y_l)$: $\log_2\!\left(\frac{1/8}{1/4}\right) = \log_2\!\left(\frac{1}{2}\right) = \mathbf{-1}$.
3. DPO preference margin: $\Delta = \hat{r}(y_w) - \hat{r}(y_l) = 2 - (-1) = \mathbf{+3}$.

Using $\log_2$ and $\beta = 2$, suppose the reference model gives $y_w$ and $y_l$ the same starting probability $\pi_{\text{ref}}(y_w) = \pi_{\text{ref}}(y_l) = \frac{1}{4}$. If the trained policy doubles the winner to $\pi_\theta(y_w) = \frac{1}{2}$ and halves the loser to $\pi_\theta(y_l) = \frac{1}{8}$, what is the DPO margin $\hat{r}_\theta(y_w) - \hat{r}_\theta(y_l)$?

3. GRPO: Online Exploration Without the Critic Network

If DPO is so cheap and stable, why did labs switch back to online RL for reasoning models like DeepSeek-R1? Because DPO is typically off-policy: it trains on a fixed dataset of pre-collected $(y_w, y_l)$ pairs. When a model is learning multi-step math or code synthesis, it needs to generate its own chains of thought, hit compiler or math errors, and learn from live verifiable rewards on the exact distribution it currently speaks.

To get PPO's live on-policy exploration without paying for a 70B Value Critic $V_\psi$, DeepSeek introduced GRPO (Group Relative Policy Optimization). For every prompt $x$, GRPO samples a small group of $G$ candidate completions $\{y_1, y_2, \dots, y_G\}$ from the current policy, scores each one with a reward function or deterministic verifier ($R_1, \dots, R_G$), and uses the group's own mean $\mu$ and standard deviation $\sigma$ as the baseline:

$$A_i = \frac{R_i - \mu}{\sigma}, \qquad \text{where }\; \mu = \frac{1}{G}\sum_{j=1}^{G} R_j,\quad \sigma = \sqrt{\frac{1}{G}\sum_{j=1}^{G}(R_j - \mu)^2}$$

Every token inside completion $y_i$ receives that normalized group advantage $A_i$ inside the familiar PPO clipped objective (with the KL penalty against $\pi_{\text{ref}}$ added directly to the loss). By replacing a neural network Critic $V_\psi$ with a 4-line group average over $G$ parallel rollouts, GRPO cuts peak memory nearly in half compared to PPO while still letting the LLM invent new reasoning strategies on the fly.

Worked Example (GRPO Group-Relative Advantages for $G = 4$ Rollouts):

Suppose a math prompt generates $G = 4$ candidate solutions with verifier scores $R = [2,\; 4,\; 4,\; 10]$:
1. Group mean ($\mu$): $\mu = \frac{2 + 4 + 4 + 10}{4} = \frac{20}{4} = \mathbf{5}$.
2. Group standard deviation ($\sigma$): Squared deviations from $5$ are $(-3)^2, (-1)^2, (-1)^2, (+5)^2 = 9, 1, 1, 25$, whose average is $\frac{36}{4} = 9$, so $\sigma = \sqrt{9} = \mathbf{3}$.
3. Normalized advantages ($A_i = (R_i - 5)/3$):
• Rollout 1 ($R_1 = 2$): $A_1 = \frac{2 - 5}{3} = \mathbf{-1.0}$ (pushed down).
• Rollouts 2 & 3 ($R = 4$): $A_{2,3} = \frac{4 - 5}{3} = \mathbf{-\frac{1}{3}}$ (slightly nudged down).
• Rollout 4 ($R_4 = 10$): $A_4 = \frac{10 - 5}{3} = \mathbf{+\frac{5}{3}}$ (strongly reinforced).

For a coding prompt, GRPO samples $G = 3$ solutions that pass $R_1 = 3$, $R_2 = 6$, and $R_3 = 9$ unit tests, giving a group standard deviation of $\sigma = 2.45$. What is the group mean $\mu$, and what is the advantage $A_2$ of the middle solution ($R_2 = 6$)?

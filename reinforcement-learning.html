Reinforcement Learning From Scratch: How Agents Learn Without an Answer Key

To see why reinforcement learning (RL) exists, compare how you teach an image classifier versus how you train a game-playing agent, a warehouse robot, or a reasoning language model. In supervised learning, a teacher hands the model an exact answer key on every single example: "This photo is a cat." If the model guesses "dog," it knows immediately on that step what the right answer was.

In reinforcement learning, there is no answer key. An agent takes a chain of actions inside an environment and only discovers several steps later whether that sequence led to a big reward or a dead end. When a warehouse robot finally reaches a charging dock for +80 points at the end of a long hallway, how does it figure out that the quiet early steps—which paid 0 points at the time—were actually the move that made the jackpot possible (credit assignment)?

Instead of waiting until the end of every run to look back, RL solves this with bootstrapping (Temporal-Difference learning): each state peeks one step ahead at its neighbor's current scorecard $V(S_{t+1})$, discounts it by $\gamma$, and updates its own score using the surprise (TD error $\delta_t$).

1. The Warehouse Hallway & Discounted Return ($G_t$)

Picture a delivery robot starting on Tile 1 ($S_0$) of a warehouse hallway (Markov Decision Process). On Tile 1, it has two choices (actions $A_0$): step left into a Spare Battery Closet that pays +30 power points right now and ends the run, or step right onto Tile 2 (paying $R_1 = 0$ points now), and from Tile 2 step onto Tile 3 (Main Supercharger), which pays +80 points ($R_2 = +80$).

Notice why judging a move by its immediate reward $R_{t+1}$ fails: stepping right onto Tile 2 pays 0 immediately, while the closet pays +30 right away. To look past immediate bribes, RL judges a move by the total stream of future rewards it leads to, called the discounted return $G_t$. Because delayed rewards carry risk and take time, each step of delay is multiplied by a discount factor $\gamma \in [0, 1]$:

$$G_t = R_{t+1} + \gamma R_{t+2} + \gamma^2 R_{t+3} + \dots = R_{t+1} + \gamma G_{t+1}$$

Worked Example (Working backward to compute $G_t$ with $\gamma = 0.5$):

Suppose a 3-step trip picks up three distinct rewards: $R_1 = 2$ on step 1, $R_2 = 6$ on step 2, and $R_3 = 20$ on step 3, with $\gamma = 0.5$ (every step of delay cuts future value in half):
1. Before the final step ($t = 2$): Only $R_3 = 20$ remains, so $G_2 = \mathbf{20}$.
2. One step earlier ($t = 1$): $G_1 = R_2 + 0.5\,G_2 = 6 + 0.5(20) = 6 + 10 = \mathbf{16}$.
3. At the start ($t = 0$): $G_0 = R_1 + 0.5\,G_1 = 2 + 0.5(16) = 2 + 8 = \mathbf{10}$.

Our robot uses $\gamma = 0.5$ (every extra step of delay cuts a reward in half). If the Closet pays $+30$ immediately on step 1, while a longer hallway pays $R_1 = 0$ on step 1, $R_2 = 0$ on step 2, and $R_3 = +80$ on step 3 (2 extra steps of delay), which path has the higher discounted return $G_0$?

2. Learning Before the Run Ends: Bootstrapping & TD Error ($\delta_t$)

In the worked example above, we waited until the robot finished the entire run and then worked backward from the end. That full-episode approach is called Monte Carlo (MC) learning. It is unbiased, but if an episode takes $10{,}000$ steps (or never ends), waiting until the end to update your scorecard $V(s)$ is painfully slow and noisy.

Temporal-Difference (TD) learning updates a tile's scorecard immediately after a single step by bootstrapping—replacing the unknown future return $G_{t+1}$ with the next tile's current estimate $V(S_{t+1})$. The difference between the new 1-step lookahead target $R_{t+1} + \gamma V(S_{t+1})$ and your old expectation $V(S_t)$ is the TD error $\delta_t$ (the "surprise"):

$$\delta_t = \underbrace{R_{t+1} + \gamma V(S_{t+1})}_{\text{TD Target}} - V(S_t), \qquad V(S_t) \leftarrow V(S_t) + \alpha\,\delta_t$$

Worked Example (Passing value backward one step at a time via TD learning):

Suppose Tile 1 currently has estimate $V(S_1) = 6$, stepping from Tile 1 to Tile 2 pays immediate reward $R_2 = 4$, and Tile 2's scorecard is currently $V(S_2) = 20$ (with discount $\gamma = 0.5$ and learning rate $\alpha = 0.5$):
1. 1-Step TD Target: $R_2 + \gamma V(S_2) = 4 + 0.5(20) = 4 + 10 = \mathbf{14}$.
2. Surprise (TD Error $\delta_1$): $\text{Target} - V(S_1) = 14 - 6 = \mathbf{+8}$ (Tile 1 was $8$ points better than expected!).
3. Nudge Tile 1's scorecard: $V_{\text{new}}(S_1) = 6 + 0.5(+8) = 6 + 4 = \mathbf{10}$.

Finally, notice one limitation of a state scorecard $V(s)$: knowing that "Tile 1 is worth 10 points" tells you how good it is to stand on Tile 1, but it doesn't tell you which button to press (Go Left vs. Go Right) unless you already have a map of which move leads to which tile! To pick moves directly without a map of the environment, RL agents also learn an action-value scorecard $Q(s, a)$ that scores every (Tile $s$, Move $a$) pair.

Tile A currently has score $V(A) = 10$. The robot steps from Tile A to Tile B, receives immediate reward $R = 0$, and sees that Tile B has scorecard $V(B) = 36$. With discount $\gamma = 0.5$ and learning rate $\alpha = 0.5$, what are the TD error $\delta$ and the updated score $V_{\text{new}}(A)$?

Why does a model-free agent that does not know the environment's transition map need $Q(s, a)$ instead of just $V(s)$ to pick its next move?

3. Comparing RL Evaluation & Scorecard Concepts

Concept Formula / Definition Tradeoff / Failure Mode When to Use
Monte Carlo (MC) Update Target $= G_t$ (actual full-episode discounted return) Zero bias, but high variance; must wait until the episode ends Short episodic tasks with noisy state estimates
Temporal-Difference (TD) Update Target $= R_{t+1} + \gamma V(S_{t+1})$ (1-step bootstrap) Slightly biased early on while $V(S_{t+1})$ is inaccurate, but low variance and updates on every step Long or continuing tasks; foundation of Q-learning and Actor-Critic
State Value $V^\pi(s)$ Expected return starting at state $s$ under policy $\pi$ Cannot pick actions directly without knowing which state $s'$ each action leads to Critic baseline in Actor-Critic / PPO ($A_t = G_t - V(s_t)$)
Action Value $Q^\pi(s, a)$ Expected return taking action $a$ at state $s$, then following $\pi$ Table size grows with number of actions $|S| \times |A|$ Model-free action selection ($\arg\max_a Q(s, a)$) in Q-Learning

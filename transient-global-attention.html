Transient Global Attention (TGlobal): How LongT5 Scales Without Side-Inputs

Suppose you ask a Transformer encoder to summarize a $16{,}000$-token scientific paper or answer a question at the very end of a book chapter using a clue from the opening paragraph. If you run standard full self-attention, every token compares itself against every other token, creating an $\ell \times \ell$ matrix of $16{,}000^2 = 256\text{ million}$ attention pairs per head in every single layer. On a standard T5 model, that quadratic memory bill crashes your GPU or TPU long before you reach $6{,}000$ tokens.

The obvious way to save memory is local sliding-window attention, where each word only looks at a small neighborhood of $r$ words to its left and right. That cuts the work down to a linear band, but it creates a severe blind spot: if a question at the end of a document needs a fact from page one, information can only crawl across the document by one local window per layer—requiring dozens of stacked layers just for two distant paragraphs to hear each other.

Earlier long-context models like ETC and BigBird bridged that gap by bolting on a separate array of persistent global memory tokens alongside the input text, which meant redesigning the data pipeline and breaking compatibility with existing pretrained checkpoints. LongT5 (Guo et al., 2022) takes a much cleaner route called Transient Global Attention (TGlobal): inside each attention layer, it temporarily pools every block of $k = 16$ consecutive tokens into a coarse summary token, lets every word attend to its local neighbors plus all of those temporary block summaries in a single hop, and throws the block summaries away as soon as the layer finishes.

1. Why Local Sliding Windows Go Blind on Long-Range Questions

To feel the difference between local hopping and a transient global bridge, shrink a document down to an $\ell = 16$-token toy sequence. A question lives at Token 16, and the fact that answers it sits all the way back at Token 1 (a gap of $15$ positions).

2. How TGlobal Builds and Discards Block Summaries on the Fly

Why did earlier global-local architectures like ETC require so much custom engineering? Because they treated global tokens as a permanent second stream of inputs that had to be pre-allocated before Layer 1 and carried through every feed-forward network. You couldn't just drop an existing T5 checkpoint into ETC without changing how text is tokenized and fed into the model.

TGlobal avoids side-inputs entirely by making its global tokens temporary scratchpad vectors inside the self-attention module. At the start of an encoder attention layer, it slices the $\ell$ input token vectors $x_1, \dots, x_\ell$ into $M = \ell / k$ fixed, non-overlapping blocks of size $k$ ($k = 16$ in LongT5). For each block $m$, it sums the $k$ token vectors together and passes that sum through T5's root-mean-square LayerNorm to produce a transient global token $g_m$.

Why is that LayerNorm step mandatory right after summing? If you sum $k = 16$ token vectors without normalizing, the resulting global vector has a magnitude roughly $\sqrt{16}$ to $16$ times larger than any individual local token vector. Feeding an unnormalized sum into dot-product attention would produce giant logits that hijack the softmax and drown out every local neighbor. Normalizing $g_m$ puts it back on the exact same scale and in the exact same embedding space $\mathbb{R}^{d_{\text{model}}}$ as the regular tokens $x_i$—which means TGlobal can project $g_m$ into keys and values using the layer's existing $W_K$ and $W_V$ matrices without adding a single new projection matrix.

Tracing transient block pooling by hand ($k = 4$ tokens, clean square-root dimension):

Take Block $m = 1$ containing $k = 4$ tokens with distinct scalar values so you can follow each number:
$$x_1 = 1, \qquad x_2 = 2, \qquad x_3 = 4, \qquad x_4 = 5$$ 1. Block sum ($s_1$): Add the $k = 4$ tokens in the block: $s_1 = 1 + 2 + 4 + 5 = \mathbf{12}$.
2. Root-mean-square normalization: Suppose across a $d = 4$-dimensional embedding vector, the raw block sum is $s_1 = [3, 3, 3, 3]$ with learned gain $\gamma = 1$. T5's root-mean-square scale is $\text{RMS}(s_1) = \sqrt{\frac{1}{4}(3^2 + 3^2 + 3^2 + 3^2)} = \sqrt{9} = \mathbf{3}$.
Your turn — dividing by $\text{RMS}(s_1) = 3$, what is the normalized first coordinate $g_{1,1} = s_{1,1} / \text{RMS}(s_1)$ of the transient global token?

$$g_m = \text{LayerNorm}\!\left(\sum_{j=1}^{k} x_{(m-1)k + j}\right), \qquad \text{Keys}(x_i) = \underbrace{\{x_j : |i - j| \le r\}}_{\text{Local window } (\le 2r+1)} \;\cup\; \underbrace{\{g_1, g_2, \dots, g_{\ell/k}\}}_{\text{Transient globals } (\ell/k)}$$
Once each query token $x_i$ computes its weighted value sum over its local window and the $\ell/k$ transient globals, $g_1, \dots, g_{\ell/k}$ are discarded. The next encoder layer synthesizes fresh global summaries from the updated token states.

To make sure a query token knows whether a global block summary comes from the adjacent paragraph or from $100$ blocks away—without treating the document as an unordered bag of blocks—TGlobal adds a small block-distance relative position bias table indexed by the distance between the query's block $\lfloor i/k \rfloor$ and global block $m$. Between that bias table and the global LayerNorm scale vector, converting a full T5 checkpoint to TGlobal adds only about $10{,}000$ parameters in Base ($50{,}000$ in XL). And when multiple short training examples are packed into a single $4{,}096$-token sequence (example packing), a block-level mask prevents tokens in Example A from attending to transient global tokens pooled from Example B.

3. The Attention Cost Math & Principle-Sentence Pre-Training

How much memory and compute does TGlobal actually save compared to full attention? Look at the two sets of keys that each of the $\ell$ query tokens attends to in a single layer. First, attending to the local sliding window of width $W \le 2r+1$ forms a narrow diagonal band of $\ell \cdot W$ pairs. Second, attending to all $\ell / k$ transient global tokens forms a skinny side rectangle of $\ell \cdot (\ell / k) = \ell^2 / k$ pairs:

$$\text{Pairs}_{\text{Full}} = \ell^2, \qquad \text{Pairs}_{\text{Local}} = \ell \cdot W \;\sim\; O(\ell r), \qquad \text{Pairs}_{\text{TGlobal}} = \ell\!\left(W + \frac{\ell}{k}\right) \;\sim\; O\!\left(\ell\!\left(r + \frac{\ell}{k}\right)\right)$$
Notice an honest mathematical detail: TGlobal still has an $\ell^2 / k$ term! It is not strictly linear as $\ell \to \infty$, but dividing the quadratic term by $k = 16$ shrinks the global matrix $16\times$, pushing the TPU out-of-memory wall from $\sim 4\text{k}$ tokens out past $16\text{k}$ tokens.

Counting attention pairs on our $\ell = 16$ toy sequence (local window $W = 3$, block size $k = 4$):

Compare the total query-key pairs evaluated in one layer for $\ell = 16$ tokens:
1. Full self-attention ($\ell^2$): Every token attends to all $16$ tokens $\implies 16 \times 16 = \mathbf{256\text{ pairs}}$.
2. Pure local attention ($\ell \times W$ with $W = 3$): Each of the $16$ tokens attends to $3$ local tokens $\implies 16 \times 3 = \mathbf{48\text{ pairs}}$ (cheap, but takes $15$ layers to cross the sequence).
3. TGlobal attention ($\ell \times (W + \ell/k)$ with $k = 4$): Pooling every $4$ tokens creates $\ell / k = 16 / 4 = \mathbf{4\text{ global tokens}}$, so each of the $16$ queries attends to $3\text{ local} + 4\text{ global} = 7\text{ keys}$:

Giving an encoder global summary hubs is only half the battle; you also have to train the model to actually route long-range themes through them. Standard T5 span corruption masks out random 3-word phrases, which a model can usually guess just by reading the ten words next door. LongT5 instead pre-trains with PEGASUS Principle Sentences Generation (PSG): it scores every sentence in a long document by its ROUGE-F1 word overlap with the rest of the text, masks out the top $20\%$ most central "topic sentences," and forces the decoder to reconstruct them all as a summary. Because those missing sentences summarize entire sections, the encoder is forced to pass document-wide signal through the transient global tokens $g_m$.

4. Where TGlobal Hits Its Limits & Hands-On Practice

TGlobal has two practical trade-offs worth keeping in mind. First, summing $k = 16$ tokens into a single vector blurs fine, single-word details outside the local radius $r$: a distant token can easily tell which 16-token block talks about a topic, but exact word-level extraction still leans on the decoder's cross-attention over the final encoder states. Second, because the output summary or answer in tasks like summarization and QA is usually short ($128$ to $512$ tokens), LongT5 only uses TGlobal inside the encoder self-attention layers while leaving the decoder completely untouched.

Transient Global Attention (TGlobal): How LongT5 Scales Without Side-Inputs

Suppose you ask a Transformer encoder to summarize a $16{,}000$-token research paper or answer a question at the very end of a book chapter using a clue from the opening paragraph. If you run standard full self-attention, every token compares itself against every other token, creating an $\ell \times \ell$ matrix of $16{,}000^2 = 256\text{ million}$ attention pairs per head in every single layer. On a standard T5 model, that quadratic memory bill crashes your hardware long before you reach $6{,}000$ tokens.

The obvious way to save memory is local sliding-window attention, where each word only looks at a small neighborhood of $r$ words to its left and right. That cuts the work down to a narrow linear band, but it creates a severe blind spot: if a question at the end of a document needs a fact from page one, information can only crawl across the document by one local window per layer—requiring dozens of stacked layers just for two distant paragraphs to hear each other.

Earlier long-context models like ETC and BigBird bridged that gap by bolting on a separate array of permanent global memory tokens alongside the input text, which meant redesigning the input pipeline and breaking compatibility with existing pretrained checkpoints. LongT5 (Guo et al., 2022) takes a much cleaner route called Transient Global Attention (TGlobal): inside each attention layer, it temporarily sums every block of $k = 16$ consecutive tokens into a coarse summary token $g_m$, lets every word attend to its local neighbors plus all of those temporary block summaries in a single hop, and throws the block summaries away as soon as the layer finishes.

1. How TGlobal Builds and Discards Block Summaries on the Fly

Why did earlier global-local architectures like ETC require so much custom engineering? Because they treated global tokens as a permanent second stream of inputs that had to be pre-allocated before Layer 1 and carried through every feed-forward network. You couldn't just drop an existing T5 checkpoint into ETC without changing how text is fed into the model.

TGlobal avoids side-inputs completely by making its global tokens temporary scratchpad vectors inside the self-attention module. At the start of an encoder attention layer, it slices the $\ell$ input token vectors $x_1, \dots, x_\ell$ into $M = \ell / k$ fixed, non-overlapping blocks of size $k$ ($k = 16$ in LongT5). For each block $m$, it sums the $k$ token vectors together and passes that sum through T5's root-mean-square LayerNorm to produce a transient global token $g_m$:

$$g_m = \text{LayerNorm}\!\left(\sum_{j=1}^{k} x_{(m-1)k + j}\right), \qquad \text{Keys}(x_i) = \underbrace{\{x_j : |i - j| \le r\}}_{\text{Local window } (\le 2r+1)} \;\cup\; \underbrace{\{g_1, g_2, \dots, g_{\ell/k}\}}_{\text{Transient globals } (\ell/k)}$$
Figure 1: In pure local attention (top), query $x_7$ only sees its $2r+1=3$ neighbors ($x_6, x_7, x_8$) and is cut off from $x_1$. In TGlobal (bottom), every $k$ tokens are summed and normalized into temporary block hubs $g_1 \dots g_{\ell/k}$; query $x_7$ attends to its local window plus every $g_m$ in a single layer, then $g_1 \dots g_{\ell/k}$ are thrown away.

Why is that LayerNorm step mandatory right after summing? If you sum $k = 16$ token vectors without normalizing, the resulting global vector has a magnitude roughly $\sqrt{16}$ to $16$ times larger than any individual local token vector. Feeding an unnormalized sum into dot-product attention would produce giant logits that hijack the softmax and drown out every local neighbor. Normalizing $g_m$ puts it back on the exact same scale and in the exact same embedding space $\mathbb{R}^{d_{\text{model}}}$ as the regular tokens $x_i$—which means TGlobal can project $g_m$ into keys and values using the layer's existing $W_K$ and $W_V$ matrices with zero extra projection weights.

To make sure a query token knows whether a global block summary comes from the adjacent paragraph or from $100$ blocks away, TGlobal adds a small block-distance relative position bias table indexed by the distance between the query's block $\lfloor i/k \rfloor$ and global block $m$. Between that bias table and the global LayerNorm scale vector, converting a full T5 checkpoint to TGlobal adds only about $10{,}000$ parameters in Base ($50{,}000$ in XL). And when multiple short training examples are packed into one $4{,}096$-token sequence (example packing), a block-level mask blocks tokens in Example A from attending to transient global tokens pooled from Example B.

2. The Attention Cost Math & Principle-Sentence Pre-Training

How much memory and compute does TGlobal actually save compared to full attention? Look at the two sets of keys that each of the $\ell$ query tokens attends to in a single layer. First, attending to the local sliding window of width $W \le 2r+1$ forms a narrow diagonal band of $\ell \cdot W$ pairs. Second, attending to all $\ell / k$ transient global tokens forms a skinny side rectangle of $\ell \cdot (\ell / k) = \ell^2 / k$ pairs:

$$\text{Pairs}_{\text{Full}} = \ell^2, \qquad \text{Pairs}_{\text{Local}} = \ell \cdot W \;\sim\; O(\ell r), \qquad \text{Pairs}_{\text{TGlobal}} = \ell\!\left(W + \frac{\ell}{k}\right) \;\sim\; O\!\left(\ell\!\left(r + \frac{\ell}{k}\right)\right)$$
Figure 2: Comparing the query-by-key attention matrices (adapted from LongT5 Figure 2). Full attention (a) computes the entire $\ell \times \ell$ square. Local attention (b) keeps only the diagonal band of radius $r$. TGlobal (c) keeps the local diagonal band and appends an $\ell \times (\ell/k)$ side rectangle (shaded) so every query token also attends to all $\ell/k$ transient block summaries.

Notice an honest detail in that equation: TGlobal still has a quadratic $\ell^2 / k$ term! It is not strictly linear as $\ell \to \infty$, but dividing the quadratic global matrix by $k = 16$ shrinks it $16\times$, pushing the TPU out-of-memory wall from $\sim 4\text{k}$ tokens out past $16\text{k}$ tokens.

Worked Example (Counting attention pairs on $\ell = 16$ tokens with window $W = 3$ and block size $k = 4$):

1. Full self-attention ($\ell^2$): Every token attends to all $16$ tokens $\implies 16 \times 16 = \mathbf{256\text{ pairs}}$.
2. Pure local attention ($\ell \cdot W$): Each of the $16$ tokens attends to $W = 3$ local tokens $\implies 16 \times 3 = \mathbf{48\text{ pairs}}$ (cheap, but blind past distance $1$).
3. TGlobal attention ($\ell(W + \ell/k)$): Pooling every $k = 4$ tokens creates $M = 16 / 4 = \mathbf{4\text{ global tokens}}$. Each of the $16$ queries attends to $3\text{ local} + 4\text{ global} = 7\text{ keys}$ $\implies 16 \times 7 = \mathbf{112\text{ pairs}}$ ($48$ local $+ 64$ global)—cutting full attention pairs by more than half even on a tiny 16-token toy sequence.

Giving an encoder global summary hubs is only half the job; you also have to train the model to route long-range themes through them. Standard T5 span corruption masks out random 3-word phrases, which a model can usually guess just by reading the ten words next door. LongT5 instead pre-trains with PEGASUS Principle Sentences Generation (PSG): it scores every sentence in a long document by its ROUGE-F1 word overlap with the rest of the text, masks out the top $20\%$ most central "topic sentences," and trains the decoder to generate all of them together as a pseudo-summary. Because those missing sentences summarize entire sections, the encoder is forced to pass document-wide signal through the transient global tokens $g_m$.

3. Comparing Long-Context Attention Mechanisms

Attention Mechanism Complexity Extra Inputs / Params Tradeoff / Failure Mode When to Use
Full Self-Attention (Vanilla T5) $O(\ell^2)$ None ($0$ extra params) Runs out of memory past $\sim 3\text{k}\text{–}5\text{k}$ tokens Short inputs ($\ell \le 1{,}024$) where exact token-to-token attention matters
Local Sliding Window (LongT5-Local) $O(\ell r)$ ($r=127$) None ($0$ extra params) Distant question and answer spans cannot interact in 1 hop Ultra-long sequences ($\ell \ge 32\text{k}$) with strictly local extraction cues
ETC / BigBird Global-Local $O(\ell(r + g))$ Requires persistent global side-input tokens & custom masks Incompatible with drop-in text-to-text T5 checkpoints Structured documents with explicit pre-segmented hierarchy nodes
Transient Global (TGlobal) (LongT5) $O(\ell(r + \ell/k))$ ($k=16$) No side-inputs; $+10\text{k}\text{–}50\text{k}$ params (block bias + LayerNorm) Pools $k=16$ tokens per block, blurring single-token details far outside radius $r$ Best drop-in default for long summarization & QA ($\ell = 4\text{k}\text{–}16\text{k}$)

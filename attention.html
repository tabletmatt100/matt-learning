How Attention Works: From First Principles to Multi-Head Math

At the center of modern artificial intelligence—from large language models like Gemini to vision transformers—lies a single elegant mathematical mechanism: Attention.

Before the 2017 landmark paper "Attention Is All You Need" (Vaswani et al.), natural language was predominantly processed using Recurrent Neural Networks (RNNs) and LSTMs. While functional, these sequential architectures suffered from a critical flaw: the information bottleneck.

1. The Problem: Sequential Bottlenecks

In an RNN, tokens are ingested one after another. At step t, the hidden state $h_t$ must compress everything learned from tokens $1, 2, \dots, t-1$:

h_t = \tanh(W_{hh} h_{t-1} + W_{xh} x_t)

If a sentence is 50 words long, information from word 1 must survive 49 successive matrix multiplications. Inevitably, gradients vanish or explode, and long-range dependencies are lost. Moreover, sequential processing prevents parallel hardware execution on GPUs.

The Attention Breakthrough: Instead of forcing a single vector to remember everything, what if every token could directly look back at every other token in the sequence and dynamically decide how much to "attend" to it?

2. The Core Metaphor: The Soft Database Lookup

To understand attention mathematically, imagine a database retrieval query:

  • Query ($Q$): What I am currently looking for (e.g., search text).
  • Key ($K$): The index or tags describing what each entry contains.
  • Value ($V$): The actual content or payload stored in the database.

In a classical database (like SQL), lookup is hard: if Query == Key, you retrieve 100% of the Value; otherwise 0%.

In neural attention, lookup is soft and continuous: We take the dot product between the Query and all Keys. If the dot product is high, the Query and Key point in similar directions in embedding space. We then pass these scores through a Softmax function to produce a probability distribution that sums to 1.0. Finally, we take a weighted sum of the Values.

3. The Exact Mathematical Formula

\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d_k}}\right) V

Let's break down each component step-by-step:

  1. Linear Projections: We take the input token embeddings $X \in \mathbb{R}^{N \times d_{\text{model}}}$ and project them with learned weights: $$Q = X W_Q, \quad K = X W_K, \quad V = X W_V$$
  2. Dot-Product Similarity ($Q K^T$): For each query token $i$ and key token $j$, computes their dot product $q_i \cdot k_j$. The result is an $N \times N$ matrix of raw scores.
  3. Scaling by $\sqrt{d_k}$: We divide by the square root of the key dimension $d_k$. (Why? See the details dropdown below).
  4. Softmax Normalization: Computed row-wise: $$A_{ij} = \frac{\exp(S_{ij})}{\sum_{k=1}^N \exp(S_{ik})}$$ Each row now forms a valid probability distribution summing to 1.
  5. Weighted Blend ($A V$): We multiply the attention weight matrix $A$ by $V$. The resulting vector for token $i$ is a linear mixture of all token values weighted by how relevant token $j$ was to token $i$.
Deep Math: Why scale by exactly $\sqrt{d_k}$? (Click to expand)

Suppose the components of $q \in \mathbb{R}^{d_k}$ and $k \in \mathbb{R}^{d_k}$ are independent random variables with zero mean and unit variance: $\mathbb{E}[q_i] = \mathbb{E}[k_i] = 0$ and $\text{Var}(q_i) = \text{Var}(k_i) = 1$.

The dot product is $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$.

The mean of each product term is $\mathbb{E}[q_i k_i] = \mathbb{E}[q_i]\mathbb{E}[k_i] = 0$.

The variance of each product term is:

\text{Var}(q_i k_i) = \mathbb{E}[q_i^2 k_i^2] - (\mathbb{E}[q_i k_i])^2 = \text{Var}(q_i)\text{Var}(k_i) = 1 \cdot 1 = 1

Since the terms are independent, the variance of the sum is the sum of the variances:

\text{Var}\left(\sum_{i=1}^{d_k} q_i k_i\right) = \sum_{i=1}^{d_k} \text{Var}(q_i k_i) = d_k

Thus, the standard deviation is $\sqrt{d_k}$. For large $d_k$ (e.g., $d_k = 64$ or $128$), the dot products grow very large in magnitude. When input values to softmax are large, the softmax function saturates, yielding gradients near zero (vanishing gradient problem). Dividing by $\sqrt{d_k}$ normalizes the variance back to 1.0!

4. Fully Worked-Out Numerical Example

Let's work through an actual example by hand with small numbers.

Imagine a sequence of 3 tokens: ["The", "dog", "barked"] ($N=3$).
Let key dimension $d_k = 2$ and value dimension $d_v = 2$.

Step 4.1: The Computed Q, K, and V Matrices

Token Query $Q$ ($d_k=2$) Key $K$ ($d_k=2$) Value $V$ ($d_v=2$)
1: "The" [1.0, 0.0] [1.0, 0.0] [2.0, 1.0]
2: "dog" [0.0, 2.0] [1.0, 1.0] [0.0, 3.0]
3: "barked" [1.0, 1.0] [0.0, 2.0] [1.0, 0.0]

Step 4.2: Compute Raw Dot Products ($Q K^T$)

Let's calculate the score matrix $S_{raw} = Q K^T$ entry-by-entry:

  • Row 1 ("The", $q_1=[1.0, 0.0]$):
    • vs $k_1=[1.0, 0.0]$: $(1.0 \times 1.0) + (0.0 \times 0.0) = \mathbf{1.0}$
    • vs $k_2=[1.0, 1.0]$: $(1.0 \times 1.0) + (0.0 \times 1.0) = \mathbf{1.0}$
    • vs $k_3=[0.0, 2.0]$: $(1.0 \times 0.0) + (0.0 \times 2.0) = \mathbf{0.0}$
  • Row 2 ("dog", $q_2=[0.0, 2.0]$):
    • vs $k_1$: $(0.0 \times 1.0) + (2.0 \times 0.0) = \mathbf{0.0}$
    • vs $k_2$: $(0.0 \times 1.0) + (2.0 \times 1.0) = \mathbf{2.0}$
    • vs $k_3$: $(0.0 \times 0.0) + (2.0 \times 2.0) = \mathbf{4.0}$
  • Row 3 ("barked", $q_3=[1.0, 1.0]$):
    • vs $k_1$: $(1.0 \times 1.0) + (1.0 \times 0.0) = \mathbf{1.0}$
    • vs $k_2$: $(1.0 \times 1.0) + (1.0 \times 1.0) = \mathbf{2.0}$
    • vs $k_3$: $(1.0 \times 0.0) + (1.0 \times 2.0) = \mathbf{2.0}$

Step 4.3: Scale by $\sqrt{d_k} = \sqrt{2} \approx 1.414$

Query \ Key1: "The"2: "dog"3: "barked"
1: "The"1.0 / 1.414 = 0.7071.0 / 1.414 = 0.7070.0 / 1.414 = 0.000
2: "dog"0.0 / 1.414 = 0.0002.0 / 1.414 = 1.4144.0 / 1.414 = 2.828
3: "barked"1.0 / 1.414 = 0.7072.0 / 1.414 = 1.4142.0 / 1.414 = 1.414

Step 4.4: Row-Wise Softmax to get Attention Weights $A$

Let's calculate Row 2 ("dog", scores $[0.000, 1.414, 2.828]$):

  • $e^{0.000} = 1.000$
  • $e^{1.414} \approx 4.112$
  • $e^{2.828} \approx 16.912$
  • $\sum = 1.000 + 4.112 + 16.912 = \mathbf{22.024}$
  • Weights: $A_{2,1} = 1.000 / 22.024 = \mathbf{0.045}$ (4.5%)
    $A_{2,2} = 4.112 / 22.024 = \mathbf{0.187}$ (18.7%)
    $A_{2,3} = 16.912 / 22.024 = \mathbf{0.768}$ (76.8%)

Notice how strongly "dog" is paying attention to "barked" (76.8%)!

Step 4.5: Multiply Weights by Values ($Z = A V$)

For Token 2 ("dog"), its new contextual representation is:

z_2 = 0.045 \cdot v_1 + 0.187 \cdot v_2 + 0.768 \cdot v_3 \\ z_2 = 0.045 \begin{bmatrix}2.0 \\ 1.0\end{bmatrix} + 0.187 \begin{bmatrix}0.0 \\ 3.0\end{bmatrix} + 0.768 \begin{bmatrix}1.0 \\ 0.0\end{bmatrix} \\ z_2 = \begin{bmatrix}0.090 \\ 0.045\end{bmatrix} + \begin{bmatrix}0.000 \\ 0.561\end{bmatrix} + \begin{bmatrix}0.768 \\ 0.000\end{bmatrix} = \mathbf{\begin{bmatrix}0.858 \\ 0.606\end{bmatrix}}

The new vector for "dog" now contains information from "The", "dog", and especially "barked"!

5. Multi-Head Attention: Why One Head is Not Enough

In a sentence like: "The animal didn't cross the street because it was too tired."

A single attention head might focus on resolving what "it" refers to (attending to "animal"). But what if another head needs to focus on syntax (verbs, prepositions), and another head needs to focus on relative position?

Multi-Head Attention (MHA) runs $h$ attention heads in parallel, each with its own projection matrices $W_Q^i, W_K^i, W_V^i$:

\text{MultiHead}(Q, K, V) = \text{Concat}(\text{head}_1, \dots, \text{head}_h) W_O \\ \text{where } \text{head}_i = \text{Attention}(Q W_Q^i, K W_K^i, V W_V^i)

6. Self-Attention vs. Cross-Attention vs. Causal Masking

Variant Where Q Comes From Where K & V Come From Use Case
Self-Attention Sequence $X$ Same sequence $X$ Encoder layers, understanding relationships inside a prompt.
Causal Self-Attention Decoder sequence $Y$ Same sequence $Y$ (with future tokens masked with $-\infty$) Autoregressive generation (GPT-style LLMs).
Cross-Attention Decoder sequence $Y$ Encoder representation $H_{enc}$ Translation, summarization, multimodal vision-language models.
PyTorch Implementation: Minimal Multi-Head Self-Attention (Click to expand) 
import torch
import torch.nn as nn
import math

class SelfAttention(nn.Module):
    def __init__(self, d_model=512, n_heads=8):
        super().__init__()
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads

        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)

    def forward(self, x, mask=None):
        batch_size, seq_len, _ = x.shape
        
        # 1. Project and split into heads: [B, L, H, d_k] -> transpose to [B, H, L, d_k]
        Q = self.w_q(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)
        K = self.w_k(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)
        V = self.w_v(x).view(batch_size, seq_len, self.n_heads, self.d_k).transpose(1, 2)

        # 2. Scaled Dot-Product: [B, H, L, L]
        scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, -1e9)

        # 3. Softmax & weighted blend
        attn_weights = torch.softmax(scores, dim=-1)
        out = torch.matmul(attn_weights, V) # [B, H, L, d_k]

        # 4. Concatenate heads and project output
        out = out.transpose(1, 2).contiguous().view(batch_size, seq_len, self.d_model)
        return self.w_o(out)

Dealing with Class Imbalance: Metrics, Thresholds, Weights & Calibration

TL;DR

  • Accuracy and ROC-AUC hide false-alarm floods: On a base rate of $\pi = 1\%$ ($100$ frauds in $10{,}000$ transactions), predicting "never fraud" scores $99\%$ accuracy. Even a model with $90\%$ recall and $95\%$ specificity (FPR $= 5\%$) produces $495$ false alarms against $90$ real catches, so precision is only $90 / 585 \approx 15.4\%$. Track PR-AUC, precision at your target recall, and expected dollar cost.
  • Move the decision threshold $t^*$ before touching the training loop: A calibrated classifier needs no resampling to act on asymmetric costs. Flag positive whenever $\hat{p}$ exceeds $t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$.
  • Keep validation and test sets at the natural base rate: Use stratified splits (or time splits). If you use class weights, undersampling, or SMOTE, apply them only inside the training fold—resampling before splitting leaks duplicate minority rows into validation (leakage).
  • Undo prior distortion when you need real probabilities: Training with positive weight $w_+$ (or undersampling negatives by $w_+$) inflates raw outputs $\tilde{p}$ toward $50\%$. Recover true calibrated log-odds by subtracting $\ln w_+$: $\text{logit}(\hat{p}) = \text{logit}(\tilde{p}) - \ln w_+$.

2. Metrics that actually move & honest evaluation splits

Every thresholded metric comes from four counts in the confusion matrix: true positives ($TP$), false negatives ($FN$), false positives ($FP$), and true negatives ($TN$).

Worked numerical trace on our $10{,}000$-transaction cohort ($100$ frauds, $9{,}900$ legit):

1. Positives ($P = 100$): Recall $= 0.90 \Rightarrow TP = \mathbf{90}$ caught, $FN = \mathbf{10}$ missed.
2. Negatives ($N = 9{,}900$): FPR $= 0.05 \Rightarrow FP = 0.05 \times 9{,}900 = \mathbf{495}$ false alarms, $TN = \mathbf{9{,}405}$ cleared.
3. Precision: $\frac{TP}{TP + FP} = \frac{90}{90 + 495} = \frac{90}{585} \approx \mathbf{15.4\%}$.
4. F1 Score: $\frac{2 \cdot P \cdot R}{P + R} = \frac{2(0.154)(0.90)}{0.154 + 0.90} = \frac{2(90)}{2(90) + 495 + 10} = \frac{180}{685} \approx \mathbf{0.263}$.

$$\text{Precision} = \frac{TP}{TP + FP}, \qquad \text{Recall (TPR)} = \frac{TP}{TP + FN}, \qquad \text{FPR} = \frac{FP}{FP + TN}$$
Why ROC-AUC flatters rare-event models: ROC plots TPR against $\text{FPR} = FP / (FP + TN)$, dividing $495$ false alarms by $9{,}900$ negatives so it looks tiny ($0.05$). PR-AUC plots Precision against Recall, dividing $90$ catches by the $585$ total alerts—exposing the $495$ false alarms immediately. A random guesser scores $\text{ROC-AUC} = 0.50$, but its $\text{PR-AUC}$ baseline is just the base rate $\pi = 0.01$.

Before comparing any two models, lock down three evaluation rules so your validation score is honest:

  • Use stratified splits (or chronological splits for time series): A random unstratified 5-fold split on $100$ positives has standard deviation $\approx \sqrt{20 \times 0.99} \approx 4.4$ positives per fold—swinging fold recall by $\pm 20\%$ purely by luck.
  • Never resample the validation or test set: Grading a model on a $50{:}50$ test set makes a $15\%$ precision detector look like a $95\%$ precision detector.
  • Never run SMOTE or oversampling before splitting: Duplicating or interpolating minority rows across the full dataset puts near-identical copies in both train and validation folds (data leakage), giving fake $0.97$ recall that collapses in production.

3. Move the threshold first: Bayes-optimal cutoffs from costs

Most people jump straight to resampling when a classifier predicts zero positives at the default $0.50$ cutoff. That is backwards: a well-trained model on $1\%$ fraud data should output probabilities around $0.01\text{–}0.30$. The cheapest, highest-leverage fix is lowering the decision threshold $t$.

If a false alarm costs $C_{FP}$ (e.g. a $\$10$ manual review or customer friction) and a missed positive costs $C_{FN}$ (e.g. a $\$90$ fraud chargeback), you should flag an example whenever the expected cost of ignoring it, $\hat{p} \cdot C_{FN}$, exceeds the expected cost of reviewing it, $(1 - \hat{p}) \cdot C_{FP}$:

$$\hat{p} \cdot C_{FN} \ge (1 - \hat{p}) \cdot C_{FP} \quad \Longleftrightarrow \quad \hat{p} \ge t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$$
Mental-math check: with $C_{FP} = \$10$ and $C_{FN} = \$90$, $t^* = \frac{10}{10 + 90} = \mathbf{0.10}$. Even a $12\%$ fraud probability is worth a $\$10$ check because $0.12 \times \$90 = \$10.80 > \$8.80$.

4. Class weights, focal loss, SMOTE & fixing distorted probabilities

When should you actually modify training instead of just moving the threshold? Only when the rare class has so few gradient updates that the model's ranking (PR-AUC) suffers. You have three training-time levers:

  • Class Weights ($w_+$): Multiply every positive example's loss by $w_+ > 1$: $L = -w_+ y \ln \hat{p} - (1-y)\ln(1-\hat{p})$. Setting $w_+ = N / P = 99$ makes the $100$ positives pull the gradient just as hard in total as the $9{,}900$ negatives, without throwing away a single majority row.
  • Focal Loss ($\gamma$): Multiplies cross-entropy by $(1 - p_t)^\gamma$: $L_{\text{focal}} = -(1 - p_t)^\gamma \ln p_t$. If an easy negative has $p_t = 0.90$ and $\gamma = 2$, its weight drops by $(1 - 0.90)^2 = \mathbf{0.01}$ ($100\times$ smaller), while a hard example with $p_t = 0.50$ keeps $(1 - 0.50)^2 = \mathbf{0.25}$ of its weight. Unlike class weights, focal loss focuses specifically on hard examples rather than inflating all positives indiscriminately.
  • Undersampling & SMOTE: Random undersampling drops majority rows to speed up training (best paired with bagging in BalancedRandomForest). SMOTE synthesizes points along line segments between $k$-nearest minority neighbors: $x_{\text{new}} = x_i + \lambda(x_{\text{nn}} - x_i)$. It can help low-dimensional tabular trees, but breaks in high dimensions (like 768-D embeddings, where straight lines between distant neighbors cut right through majority territory).

The probability distortion trap & exact prior-shift correction:

If you weight positives by $w_+ = 9$ (or undersample negatives $9\times$), you multiplied the positive prior odds by $9$. Your model's raw output $\tilde{p}$ is no longer calibrated to reality:

$$\frac{\tilde{p}}{1 - \tilde{p}} = w_+ \cdot \frac{\hat{p}}{1 - \hat{p}} \quad \Longrightarrow \quad \hat{p} = \frac{\tilde{p}}{\tilde{p} + w_+(1 - \tilde{p})} = \sigma\big(\text{logit}(\tilde{p}) - \ln w_+\big)$$

Concrete mental-math trace: Suppose you train with $w_+ = 9$ and the model outputs a raw score of $\tilde{p} = 0.75$ (raw odds $\frac{0.75}{0.25} = 3{:}1$):
1. Divide the raw odds by $w_+ = 9$: true odds $= \frac{3}{9} = \frac{1}{3}$.
2. Convert odds $\frac{1}{3}$ back to probability: $\hat{p} = \frac{1}{1 + 3} = \mathbf{0.25}$ (or using the formula directly: $\frac{0.75}{0.75 + 9(0.25)} = \frac{0.75}{3.00} = \mathbf{0.25}$).

The 4-Step Order of Operations on a New Imbalanced Problem

Without scrolling up, list in order: (1) how you split and evaluate the data, (2) the first decision-rule change you make before altering the training loss, and (3) what you must fix if you train with class weights or undersampling and downstream code needs real probabilities.

Canonical checklist: (1) Evaluate honestly: Use stratified (or time-based) splits, keep validation/test sets at the real base rate $\pi$, and measure PR-AUC or expected dollar cost rather than accuracy or ROC-AUC. (2) Move the threshold first: Train a standard unweighted baseline and tune the decision cutoff $t^* = \frac{C_{FP}}{C_{FP} + C_{FN}}$ (or to match your review budget). (3) Weight & recalibrate: If ranking still lags, try class weights $w_+$ or focal loss inside training folds only, then apply the prior-shift correction $\hat{p} = \frac{\tilde{p}}{\tilde{p} + w_+(1-\tilde{p})}$ (or Platt/isotonic calibration on an untouched validation fold) to restore true probabilities.

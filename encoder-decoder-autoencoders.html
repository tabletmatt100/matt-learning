Encoder-Decoder Architectures & Autoencoders: Bottlenecks, Latents & Cross-Attention

In deep learning, the phrase "encoder-decoder" gets used for two architectures that look almost identical on a whiteboard but solve opposite problems. Both split a neural network into two halves: an encoder that reads the raw input and builds an internal representation, and a decoder that turns that representation into an output.

In an autoencoder, the target output is the input itself ($\hat{x} \approx x$). Why train a network just to copy its input? Because if you force a 1,000-dimensional input through a narrow 10-number latent bottleneck $z$ in the middle, the network doesn't have enough bandwidth to memorize raw pixel or token noise. It has to discover the underlying coordinates of the data—compression by starvation.

In a Sequence-to-Sequence (Seq2Seq) encoder-decoder (like T5 for text or Whisper for speech-to-text), the output is a completely different sequence $y_{1:T}$ from the input $x_{1:S}$. Here, squeezing a 100-word paragraph into one tiny vector $z$ is actually a bug, not a feature: the decoder forgets the start of the sentence before it finishes translating. Modern Transformer encoder-decoders keep the two-stage split—a bidirectional encoder for reading and a causal decoder for writing—but replace the single-vector bottleneck with cross-attention over every encoded input token.

1. Autoencoders and the Hourglass Bottleneck ($x \to z \to \hat{x}$)

Suppose each input $x \in \mathbb{R}^D$ is a vector of $D$ features, and you have zero human labels. An undercomplete autoencoder passes $x$ through an encoder $f_\phi(x)$ that squeezes it down to a compact latent code $z \in \mathbb{R}^d$ (with $d \ll D$), and then passes $z$ through a decoder $g_\theta(z)$ that tries to reconstruct $\hat{x} \in \mathbb{R}^D$ as closely as possible:

$$z = f_\phi(x) \in \mathbb{R}^d, \qquad \hat{x} = g_\theta(z) \in \mathbb{R}^D, \qquad \mathcal{L}_{\text{rec}} = \frac{1}{D}\sum_{i=1}^{D}(x_i - \hat{x}_i)^2$$

Why must the bottleneck dimension $d$ be smaller than $D$? Imagine what happens if you set $d = D$. The network can achieve a perfect reconstruction loss $\mathcal{L}_{\text{rec}} = 0$ by setting both the encoder and decoder to the identity matrix ($z = x$ and $\hat{x} = z$). It copies every coordinate verbatim and learns nothing about the data. When you force $d \ll D$ (say, squeezing 3 correlated sensor readings into $d = 1$ number), the encoder has to find the single underlying axis that explains all three sensors at once.In fact, if $f_\phi$ and $g_\theta$ are purely linear matrices, a trained undercomplete autoencoder spans the exact same subspace as Principal Component Analysis (PCA).

What if you want a wide latent layer ($d > D$) so each hidden neuron can represent one specific concept? To stop a wide network from trivially copying $x$, you add a different bottleneck constraint: a Denoising Autoencoder (DAE) corrupts the input with noise ($\tilde{x} = x + \text{noise}$) and forces the decoder to reconstruct the clean original $x$, while a Sparse Autoencoder (SAE) adds an $L_1$ sparsity penalty $\lambda \sum_j |z_j|$ so only a tiny handful of latent neurons can fire on any single token—the exact tool researchers use today to unpack superposed features inside LLM residual streams.

Worked Example (Compressing $D = 3$ features through a $d = 1$ bottleneck by hand):

Suppose an input vector $x = [2,\; 4,\; 6]^\top$ enters a linear autoencoder with bottleneck size $d = 1$:
1. Encode ($D=3 \to d=1$): Suppose the encoder averages the coordinates with weights $w_{\text{enc}} = [\frac{1}{6},\; \frac{1}{6},\; \frac{1}{6}]$, giving latent code $z = \frac{2 + 4 + 6}{6} = \mathbf{2}$.
2. Decode ($d=1 \to D=3$): The decoder multiplies $z = 2$ by prototype vector $w_{\text{dec}} = [1,\; 2,\; 3]^\top$, reconstructing $\hat{x} = 2 \times [1,\; 2,\; 3]^\top = \mathbf{[2,\; 4,\; 6]^\top}$ with $\mathcal{L}_{\text{rec}} = 0$.
3. Noise filtering on a corrupted input: If a noisy sensor sends $x_{\text{noisy}} = [2,\; 4,\; 9]^\top$ and gives $z = 2$, the decoder still outputs $\hat{x} = [2,\; 4,\; 6]^\top$. The per-coordinate squared errors are $(2-2)^2 = 0$, $(4-4)^2 = 0$, and $(9-6)^2 = 9$, so the MSE is $\mathcal{L}_{\text{rec}} = \frac{0 + 0 + 9}{3} = \mathbf{3}$.

A $D = 3 \to d = 1 \to D = 3$ autoencoder uses decoder $\hat{x} = z \cdot [1,\; 2,\; 3]^\top$. If an input $x = [4,\; 8,\; 9]^\top$ is encoded to the single latent number $z = 3$, what is the reconstructed vector $\hat{x}$ and its mean squared reconstruction loss $\mathcal{L}_{\text{rec}} = \frac{1}{3}\sum_{i=1}^3 (x_i - \hat{x}_i)^2$?

2. Why Standard Autoencoders Can't Generate New Data (and How VAEs Fix It)

Once you have trained a standard autoencoder on faces or sentences, it is tempting to skip the encoder, pick a random vector $z$ in the latent space, and feed $z$ into the decoder $g_\theta(z)$ to generate a brand-new sample. If you try this, the decoder usually outputs garbage.

Why? Because a deterministic autoencoder only cares about reconstructing the specific points in your training set. It packs training examples into tiny, disconnected islands in latent space and leaves huge empty "dead zones" between them where the decoder has never been trained.

A Variational Autoencoder (VAE) closes those dead zones by turning each input into a fuzzy probability cloud instead of a single sharp point. For every input $x$, the encoder predicts a mean vector $\mu$ and a standard deviation vector $\sigma$, and draws a noisy latent sample $z$ using the reparameterization trick (multiplying standard normal noise $\epsilon \sim \mathcal{N}(0, I)$ by $\sigma$ and adding $\mu$ so backpropagation can still differentiate with respect to $\mu$ and $\sigma$):

$$z = \mu_\phi(x) + \sigma_\phi(x) \odot \epsilon, \quad \epsilon \sim \mathcal{N}(0, I), \qquad \mathcal{L}_{\text{VAE}} = \mathcal{L}_{\text{rec}}(x, \hat{x}) + \beta\, D_{\text{KL}}\bigl(\mathcal{N}(\mu, \sigma^2) \,\|\, \mathcal{N}(0, I)\bigr)$$

The two terms in $\mathcal{L}_{\text{VAE}}$ play tug-of-war: the reconstruction loss tries to separate different inputs and shrink $\sigma \to 0$ so the decoder doesn't get confused, while the KL prior penalty pulls every cloud's center $\mu$ back toward the origin $0$ and inflates $\sigma$ toward $1$. Because adjacent probability clouds overlap inside the unit Gaussian ball $\mathcal{N}(0, I)$, every point near the origin is now decodable.

For a 1D latent variable, a VAE encoder outputs mean $\mu = 2$ and standard deviation $\sigma = 0.5$. On the forward pass, the random noise generator draws $\epsilon = -2$. What latent value $z = \mu + \sigma \epsilon$ is fed to the decoder, and why is $\epsilon$ sampled externally instead of calling $z \sim \mathcal{N}(\mu, \sigma^2)$ directly?

3. Sequence-to-Sequence Encoder-Decoders and Cross-Attention

Now shift from reconstructing a fixed-size vector ($x \to \hat{x}$) to translating a source sequence $x_{1:S}$ of length $S$ into a target sequence $y_{1:T}$ of length $T$. In 2014, the first RNN Seq2Seq models copied the autoencoder blueprint literally: the encoder read all $S$ input words and compressed the entire sentence into a single final hidden state $z \in \mathbb{R}^d$, and the decoder tried to generate the translation from $z$ alone.

That single-vector information bottleneck worked fine for 8-word sentences and collapsed on 40-word sentences. Why force an English-to-French decoder to remember every noun, date, and number inside one fixed vector when the encoded source tokens are sitting right there in memory?

Modern Transformer encoder-decoders (like the original 2017 Vaswani Transformer, T5, BART, and Whisper) eliminate the single-vector bottleneck completely. First, a bidirectional encoder runs full self-attention across the $S$ input tokens and outputs a memory bank of $S$ contextualized vectors $H^{\text{enc}} \in \mathbb{R}^{S \times d}$. Then, at each layer of the causal decoder, after the target tokens attend to their own past prefix via causally masked self-attention, they run a cross-attention sub-layer into the encoder's memory bank:

$$\text{CrossAttn}\bigl(Q_{\text{dec}},\; K_{\text{enc}},\; V_{\text{enc}}\bigr) = \text{softmax}\!\left(\frac{Q_{\text{dec}} K_{\text{enc}}^\top}{\sqrt{d_k}}\right) V_{\text{enc}}$$

Notice the asymmetry: Queries $Q_{\text{dec}} \in \mathbb{R}^{T \times d_k}$ come from the decoder (what the target token currently being written is looking for), while Keys $K_{\text{enc}} \in \mathbb{R}^{S \times d_k}$ and Values $V_{\text{enc}} \in \mathbb{R}^{S \times d_v}$ come from the encoder ($H^{\text{enc}}$). Because $H^{\text{enc}}$ doesn't change while the decoder generates token after token, you only run the bidirectional encoder once per prompt—and even reuse its projected $K_{\text{enc}}, V_{\text{enc}}$ tensors across every autoregressive decoding step.

Worked Example (One Decoder Step Querying $S = 2$ Encoder Tokens via Cross-Attention):

Suppose head dimension is $d_k = 4$ (so $\sqrt{d_k} = \mathbf{2}$) and the encoder produced $S = 2$ source tokens with keys $k_1 = [2, 0, 0, 0]$, $k_2 = [0, 2, 0, 0]$ and scalar values $v_1 = 10$, $v_2 = 50$:
1. Decoder query at step $t$: The decoder emits $q_t = [1, 1, 0, 0]$.
2. Scaled dot-product scores ($q_t \cdot k_j / \sqrt{4}$):
• Source token 1: $\frac{1(2) + 1(0)}{2} = \frac{2}{2} = \mathbf{1}$.
• Source token 2: $\frac{1(0) + 1(2)}{2} = \frac{2}{2} = \mathbf{1}$.
3. Cross-attention output: Equal scores $[1, 1]$ give softmax weights $[\frac{1}{2}, \frac{1}{2}]$, so the decoder pulls $\frac{1}{2}(10) + \frac{1}{2}(50) = \mathbf{30}$ from the encoder memory bank.

A speech-to-text encoder-decoder processes $S = 100$ encoded audio frames in the encoder and has generated $T = 6$ text tokens so far in the decoder.

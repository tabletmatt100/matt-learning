Class imbalance · Part 6 Calibration

Fixing probabilities, other angles, and a checklist

TL;DR

  • Undersampling, oversampling, class weights and focal loss all inflate predicted probabilities. Ranking survives; the numbers themselves don't.
  • If you only changed the class balance, an exact fix exists: subtract $\text{logit}(\pi') - \text{logit}(\pi)$ from the model's log-odds. A 50:50-trained "0.8" is really about 0.039 at a 1% base rate.
  • When that shortcut isn't enough (SMOTE, boosted trees, focal loss), fit Platt scaling or isotonic regression on held-out data with the real class balance. With around 100 positives, use Platt.
  • Check calibration with a reliability diagram and the Brier score. AUC can't tell you anything here, because calibration doesn't change the ranking.
  • Other levers: anomaly detection for unseen patterns, more real positives, augmentation, two-stage models, and reframing the label.
  • The checklist at the end is the order I'd work in on a new problem, with links back to every part of the series.

1. Why rebalancing breaks probabilities

The running example, in case you landed here first: a card-fraud model scoring 10,000 transactions, of which 100 are fraud (a 1% base rate, 99:1). At its tuned threshold it gets TP = 80, FN = 20, FP = 320, TN = 9,580 (see the confusion matrix in part 1).

If you only need a ranking, or a yes/no decision with a tuned threshold, you can skip most of this page. But if anything downstream uses the number as a probability (expected loss, pricing, combining with other models, showing "12% risk" to a doctor), then resampling and weighting have broken it. A model trained on 50:50 data believes fraud is 50% common, and its outputs reflect that belief. Calibration is the property you need to restore.

The mechanism is simple. A classifier trained with log loss learns $P(\text{fraud} \mid x)$ for the data it was shown. Undersampling the 9,900 legit transactions down to 100 doesn't change what fraud looks like; it changes how often fraud appears. So the learned odds are the true odds multiplied by a constant: $(0.5/0.5)/(0.01/0.99) = 99$. Class weights do the same thing through the loss, and focal loss does something similar but messier, because it reweights by difficulty rather than by class.

A model trained on a 50:50 undersample scores next month's 10,000 transactions. Finance adds up the predicted probabilities to forecast how many frauds to expect. The sum is about 2,800. The real count turns out to be about 100. What's the most likely explanation?

2. Prior-shift correction

If the only thing you changed was the class balance (undersampling, oversampling, or class weights), there's an exact fix, usually called prior-shift correction. Training with positive rate $\pi'$ instead of the true $\pi$ shifts the model's log-odds by a constant. Undo it:

$$\text{logit}(p) = \text{logit}(p') + \text{logit}(\pi) - \text{logit}(\pi'), \qquad \text{logit}(x) = \ln\frac{x}{1-x}$$

Equivalently, in probability form:

$$p = \frac{p' \,\frac{\pi}{\pi'}}{p'\,\frac{\pi}{\pi'} + (1-p')\,\frac{1-\pi}{1-\pi'}}$$

We undersampled to 50:50 ($\pi' = 0.5$). The real rate is $\pi = 0.01$. The model outputs $p' = 0.8$ for a transaction.

Ratios: $\pi/\pi' = 0.01/0.5 = 0.02$ and $(1-\pi)/(1-\pi') = 0.99/0.5 = 1.98$.

Numerator: $0.8 \times 0.02 = 0.016$.

Denominator: $0.016 + 0.2 \times 1.98 = 0.016 + 0.396 = 0.412$.

$p = 0.016 / 0.412 \approx 0.039$.

The model's "80% fraud" is really about 3.9%. Still four times the base rate, so a useful signal, but nowhere near 80%. Check via logits: $\text{logit}(0.8) = 1.386$, $\text{logit}(0.01) = -4.595$, $\text{logit}(0.5) = 0$. Sum: $1.386 - 4.595 - 0 = -3.209$. Then the sigmoid gives $\sigma(-3.209) = 0.039$.

The class weight version

For class weights, use the same formula with the implied training prior. Weights $w_1, w_0$ multiply the odds by $w_1/w_0$, so subtract $\ln(w_1/w_0)$ from the logit. "Balanced" weights at 99:1 give $\ln 99 = 4.595$, the same as undersampling to 50:50.

sklearn's balanced weights for our data: $w_1 = 10{,}000/(2 \times 100) = 50$ and $w_0 = 10{,}000/(2 \times 9{,}900) = 0.505$. Ratio: $50/0.505 = 99$. Correction: subtract $\ln 99 = 4.595$, identical to the 50:50 case, so a weighted "0.8" also becomes 0.039.

A gentler weight, class_weight={0: 1, 1: 10}: subtract $\ln 10 = 2.303$. For $p' = 0.8$: $1.386 - 2.303 = -0.916$, and $\sigma(-0.916) = 0.286$. The implied training prior is $10/(99+10) = 0.092$, which is close to the 0.0909 (10:1) option in the widget below.

Aside: the same formula in Dal Pozzolo's notation

Dal Pozzolo et al. (2015) write the undersampling correction in terms of $\beta$, the probability that a negative is kept: $p = \beta p_s / (\beta p_s - p_s + 1)$. We kept 100 of 9,900 legit transactions, so $\beta = 100/9{,}900 = 0.0101$. With $p_s = 0.8$: numerator $0.0101 \times 0.8 = 0.00808$; denominator $0.00808 - 0.8 + 1 = 0.20808$; $p = 0.0388$. Same answer as above, as it must be: it's the same algebra with the sampling rate in place of the two priors.

Their paper also makes a point worth remembering: undersampling increases the variance of the classifier (fewer rows), so the corrected probabilities are unbiased but noisier. That's one reason bagging several undersampled models (a balanced ensemble, part 5) tends to beat a single one.

3. Platt scaling and isotonic regression

The prior-shift formula assumes the model was calibrated on its training distribution to begin with. Boosted trees, SVMs, focal-loss networks and SMOTE-trained models often aren't, and SMOTE also changes the shape of the minority distribution, not just its frequency. In those cases, fit a calibration map on a held-out set that has the true class balance:

  • Platt scaling: fit a logistic regression $p = \sigma(a s + b)$ on the model score $s$. Two parameters, works with little data. Note that it can learn the prior-shift offset itself (that's the $b$).
  • Isotonic regression: fit any monotone step function. More flexible, but needs more data, and with only a few hundred positives it overfits. With 100 positives I'd use Platt.

The held-out part is the whole game. If the calibration set has been resampled, or contains synthetic rows, the calibrator learns the training prior all over again. The same leakage rules from part 2 apply: calibration data must come from untouched, real-balance data, kept apart from both training and test.

How Platt absorbs the prior shift. Suppose the model's score is the log-odds from a 50:50-trained model, $s = \text{logit}(p')$. The exact correction is $\text{logit}(p) = s - 4.595$. That's a Platt map with $a = 1$, $b = -4.595$. For our $p' = 0.8$: $s = 1.386$, so $\sigma(1 \times 1.386 - 4.595) = \sigma(-3.209) = 0.039$. If the model was also overconfident, Platt would fit $a$ below 1 to shrink the scores toward each other as well.

For multiclass neural networks, the usual one-parameter cousin is temperature scaling. It fixes overconfidence but not a prior shift, since it can't add a per-class offset; for that you'd add a bias per class (vector scaling).

Code: prior correction and calibration 
import numpy as np
from scipy.special import logit, expit

def correct_prior(p_train, pi_train, pi_true):
    return expit(logit(p_train) + logit(pi_true) - logit(pi_train))

correct_prior(0.8, 0.5, 0.01)   # -> 0.0388

from sklearn.calibration import CalibratedClassifierCV, calibration_curve
from sklearn.metrics import brier_score_loss

# Option 1: wrap and calibrate with internal CV (calibration folds keep true prior
# as long as resampling lives inside the base estimator's pipeline)
cal = CalibratedClassifierCV(pipe, method="sigmoid", cv=5).fit(X_train, y_train)

# Option 2: prefit model + separate untouched calibration set
from sklearn.frozen import FrozenEstimator        # sklearn >= 1.6

4. Checking calibration: reliability diagrams and Brier score

Check the result with a reliability diagram and the Brier score, not with AUC. Calibration doesn't change ranking, so AUC won't move.

A reliability diagram groups predictions into bins, then plots the average predicted probability in each bin (x) against the fraction that were actually positive (y). A calibrated model sits on the diagonal. A model trained at 50:50 and deployed at 1% sits far below it: it says 0.5 where the truth is 0.01. On imbalanced data most points crowd into the bottom-left corner, which is fine and expected, since most transactions are low risk.

The Brier score is the mean squared error of the probabilities:

$$\text{Brier} = \frac{1}{n}\sum_{i=1}^{n} (p_i - y_i)^2$$

Baseline first: predict 1% for every transaction, no model at all.

Each of the 100 frauds contributes $(0.01 - 1)^2 = 0.9801$, total $98.01$.

Each of the 9,900 legit transactions contributes $(0.01 - 0)^2 = 0.0001$, total $0.99$.

Brier $= (98.01 + 0.99)/10{,}000 = 99/10{,}000 = 0.0099$. That's $\pi(1-\pi)$, and it's the number any model must beat.

Now one transaction where our 50:50-trained model says 0.8 and it turns out legit. Raw: $(0.8 - 0)^2 = 0.64$. Corrected to 0.039: $(0.039 - 0)^2 = 0.0015$. The raw model pays 400 times as much for that one row.

Brier is a proper scoring rule, so honest probabilities minimise it, and it rewards both ranking and calibration. Log loss is the other common one; it punishes confident mistakes much harder. People sometimes also quote expected calibration error, which is just the weighted gap between the dots and the diagonal.

Why calibration doesn't change AUC

ROC-AUC is the probability that a random fraud scores higher than a random legit transaction. It only looks at order. Prior-shift correction subtracts the same constant from every logit, and Platt scaling with $a > 0$ is a strictly increasing function, so the order of every pair is unchanged and AUC is identical to the last decimal. The same goes for PR-AUC, since precision and recall at each cut depend only on which transactions are above it.

Isotonic regression is the one exception, and a small one: its step function maps a range of scores to the same value, creating ties. Ties count as half, so AUC usually drops a little (often in the third decimal). If you see a big AUC change after calibrating, something else changed too.

Four transactions. Predicted probabilities and outcomes: 0.9 (fraud), 0.2 (legit), 0.1 (legit), 0.6 (fraud). What is the Brier score?

5. Other angles

Treat it as anomaly detection

When positives are extremely rare (dozens in millions), or when new kinds of positives keep appearing that look nothing like the old ones, a supervised classifier has little to learn from. Modelling "normal" and flagging deviations can work better: Isolation Forest, one-class SVM, autoencoder reconstruction error, or plain density estimates. These won't beat a supervised model on the fraud patterns you've labelled, but they can catch the ones you haven't. In fraud teams it's common to run both and send the union to review.

Get more minority data

Boring and usually the biggest win. Some ways: extend the time window, pull in related labelled datasets, mine your false negatives (the cases that were caught later by other means), and use active learning to send the most uncertain unlabelled cases to annotators. An extra 200 real positives is worth more than 10,000 synthetic ones.

Active learning is cheap to try. With 1% fraud, a random sample of 1,000 transactions sent to annotators yields about 10 frauds. A batch picked from the scores near your threshold might be 10% to 30% fraud, so the same labelling budget buys ten times the positives, and the ones it finds are the confusing cases the model most needs.

Data augmentation

For images, audio and text, domain-aware augmentation (crops, flips, noise, pitch shift, back-translation, paraphrasing with an LLM) applied to the minority class is a much better version of oversampling than SMOTE, because the augmented examples stay on the data manifold. Augment only training data, same rule as before.

Two-stage models

Use a cheap high-recall first stage to throw out the obvious negatives (say 95% of traffic), then train a second, more expensive model on what's left. The second stage sees a much less skewed problem: if stage one keeps 95 of 100 frauds and 500 of 9,900 legit, stage two works at $95/595 \approx 16\%$ positives instead of 1%. Search ranking and ad systems are built this way (a cascade). The cost is two models to maintain, and stage one's misses can never be recovered.

Reframe the label

Sometimes the rare class can be decomposed or merged. Predicting "chargeback within 90 days" might be rarer and noisier than predicting a precursor event that's more common. Grouping a dozen rare intents into an "other" class and handling it separately is another version of the same idea.

6. Order of operations

This is roughly the order I go in on a new imbalanced problem, and it doubles as a map of the series. Most projects stop somewhere around step 5.

  1. Decide what a mistake costs. Even rough numbers ("a miss is about 40 times worse than a false alarm") or a constraint ("we can review 300 cases a day") settle most later arguments. Part 3.
  2. Set up honest evaluation. Stratified (or time-based) splits, a test set with the production class balance, and metrics that see the minority class: PR-AUC, recall at your operating point, precision, MCC. Put the always-majority baseline in the results table. Part 2 for splits, part 1 for metrics.
  3. Train a plain strong model with no tricks. Gradient boosting for tabular, a pretrained backbone for images/text. Look at PR-AUC. Ranking quality is fixed at this point; everything else is about where you cut. Part 1: PR-AUC vs ROC-AUC.
  4. Tune the threshold on validation data, from costs, a recall target, or a review budget. Often this alone solves the problem people were blaming on imbalance. Part 3.
  5. Try class weights (or scale_pos_weight), searching a few values below and at the full ratio. Re-tune the threshold each time. Part 4.
  6. Try focal loss if you're training a deep model with masses of easy negatives. Part 4: focal loss.
  7. Try resampling (undersampling for speed, SMOTE variants for low-dimensional numeric data, a balanced ensemble) inside the CV pipeline. Keep it only if it beats step 5 on validation. Part 5, and part 2 on leakage.
  8. Fix probabilities if anything downstream needs them: prior-shift correction, then Platt or isotonic on untouched data. Check with a reliability diagram. This page, sections 2 to 4.
  9. Get more positives. Really this belongs in parallel with everything above. Label mining, active learning, augmentation. Section 5.
  10. Consider reframing: anomaly detection for unseen patterns, two-stage models for extreme skew, or a different label. Section 5.

One last opinion. "Imbalance" is often blamed for problems that are really about weak features or too few positives in absolute terms. 100 positives at 1% and 100 positives at 0.01% are harder for very different reasons; the second has the same amount of signal but far more chances for false alarms. If PR-AUC from step 3 is close to the base rate, no rebalancing trick will save you, and the next hour is better spent on features or labels.

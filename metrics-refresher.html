Classification Metrics Refresher: From Type I/II Errors to ROC-AUC and PR-AUC

TL;DR

  • Two kinds of mistakes: A Type I error (False Positive, $FP$) is a false alarm on a real negative. A Type II error (False Negative, $FN$) is a missed real positive.
  • Row vs. column denominators: Recall and Sensitivity are the exact same ratio—caught positives divided by all real positives ($\frac{TP}{TP + FN}$). Specificity is cleared negatives divided by all real negatives ($\frac{TN}{TN + FP}$). Precision switches to the predicted denominator: real positives divided by all flagged alerts ($\frac{TP}{TP + FP}$).
  • Why you need both ROC-AUC and PR-AUC: When positives are rare, a huge True Negative ($TN$) pool keeps the False Positive Rate ($\text{FPR} = \frac{FP}{FP + TN}$) tiny, making ROC-AUC look flattering even when false alarms drown out real hits in PR-AUC.

Type I Error ($FP$) Count of false alarms How many innocent/healthy cases did we wrongly flag?
Type II Error ($FN$) Count of missed positives How many real threats/cases slipped right past us?
Recall = Sensitivity ($\text{TPR}$) $\dfrac{TP}{TP + FN}$ Of all actual positives, what fraction did we catch?

Precision ($\text{PPV}$) $\dfrac{TP}{TP + FP}$ When the alarm rings (predicted positive), how often is it real?

Memory anchor for Type I vs. Type II and the three ratios:

• Type I ($FP$) vs. Type II ($FN$): Think of the boy who cried wolf. First time (Type I), the villagers believe a wolf is there when there is none (false alarm, $FP$). Second time (Type II), they believe no wolf is there when a real wolf attacks (missed detection, $FN$).
• Recall = Sensitivity = $\text{TPR}$: Machine learning calls it recall; medicine calls it sensitivity. Both divide $TP$ by the top row ($TP + FN = 10$).
• Specificity vs. Precision: Specificity looks only at the bottom row of healthy people ($\frac{TN}{TN + FP} = \frac{84}{100}$). Precision looks down the left column of triggered alarms ($\frac{TP}{TP + FP} = \frac{8}{24}$) and completely ignores $TN$.

2. Interactive ROC-AUC vs. PR-AUC Curves

Precision, recall, and specificity only evaluate one single threshold $t$. If you lower $t$, you catch more positives (recall goes up, Type II errors drop) at the price of more false alarms (Type I errors rise, precision and specificity drop).

To judge a model's raw ranking quality across every possible cutoff at once, we sweep $t$ from strict to loose and plot two curves:

  • ROC Curve (Receiver Operating Characteristic): Plots $\text{TPR}$ (Sensitivity/Recall) on the y-axis against $\text{FPR} = 1 - \text{Specificity}$ on the x-axis. ROC-AUC equals the probability that a randomly chosen positive gets a higher score than a randomly chosen negative.
  • PR Curve (Precision-Recall): Plots Precision on the y-axis against Recall on the x-axis. Because neither axis uses $TN$, PR-AUC exposes false-alarm flooding on rare classes.

3. When Each Metric Matters Most

Metric Core Strength Blind Spot Use It When...
Recall / Sensitivity Penalizes Type II errors ($FN$) directly Can hit $100\%$ by flagging everyone Missing a positive is catastrophic (cancer screening, brake failure, fraud net)
Specificity Measures how cleanly negatives are cleared Ignores how many positives exist Pairing with sensitivity in clinical diagnostics where rule-in/rule-out rates must hold across clinics
Precision Penalizes Type I errors ($FP$) relative to real hits Can be gamed by only flagging 1 ultra-safe case Every triggered alert costs human review time, customer friction, or a risky treatment
ROC-AUC Threshold-free ranking score; invariant to class balance ($0.5$ = random) Looks near-$0.90$ even when false alarms flood a rare class Classes are roughly balanced, or you want pure pairwise ranking independent of prevalence
PR-AUC Ignores $TN$; reflects real-world alert quality across thresholds Baseline equals the base rate ($\frac{N_{\text{pos}}}{N_{\text{total}}}$), not $0.5$ Positives are rare ($<10\%$) and you care whether top-ranked alerts are actually positive

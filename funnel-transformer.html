Funnel-Transformer: Compressing Token Sequences Without Losing Word-Level Detail

When you read a movie review to decide whether it is positive or negative, you don't hold onto every individual word separately from start to finish. As you read, adjacent words merge into phrases, and phrases merge into higher-level ideas. Yet a standard Transformer encoder like BERT keeps the exact same number of token vectors $T$ across every single layer—burning the same self-attention and feed-forward compute in Layer 12 on individual word slots that have already blended into redundant phrase representations by Layer 4.

Why not just shrink the sequence length in half every few layers by averaging adjacent token pairs, the same way a vision CNN downsamples an image grid? If you try that naively, two things break right away. First, blindly averaging pairs of tokens before attention runs lets common filler words drown out sharp, high-signal words like "not". Second, pretraining tasks like Masked Language Modeling (MLM) need a distinct prediction at every original token position, which is impossible if your final layer only has a quarter of the tokens left.

Funnel-Transformer (Dai et al., NeurIPS 2020) solves both problems with two simple architectural tweaks: at block boundaries, it pools only the queries $Q$ while letting them attend over the full unpooled keys $K$ and values $V$ (Pool-Query-Only), and when a task needs token-level outputs, it restores the full sequence in a single step by adding the first block's uncompressed token vectors back onto the upsampled bottleneck (Bridge Upsampling).

1. Why Averaging Everything Before Attention Destroys Signal

To see why naive pooling fails, follow a two-word phrase entering a compression boundary where we want to cut the sequence length in half. Word 1 is a critical negation word ("not") with scalar value $v_1 = 2$, and Word 2 is a filler intensifier ("very") with scalar value $v_2 = 10$.

If we let a query inspect those two words individually before merging them, their unpooled keys tell the model that "not" is three times as important as "very", assigning softmax attention weights $\alpha_1 = \frac{3}{4}$ to "not" and $\alpha_2 = \frac{1}{4}$ to "very". Compare what happens under two different ways of halving the sequence:

  • Case A (Naive Pre-Pooling — pool $Q, K, V$ first): You average the two token vectors before attention runs into a single vector $h'_1 = \frac{2 + 10}{2} = \mathbf{6}$. Attention over that single merged slot can only output $\mathbf{6}$.
  • Case B (Pool-Query-Only — pool $Q = h'$, keep unpooled $K, V = h$): You still average the two tokens to create one compressed query $h'_1$, which cuts the output length in half. However, that compressed query attends directly over the two unpooled values $v_1 = 2$ and $v_2 = 10$ with learned weights $\alpha = [\frac{3}{4},\; \frac{1}{4}]$.

2. How Pool-Query-Only Attention Compresses a Block

In a Funnel encoder, the layers are grouped into $M$ blocks of progressively shorter sequence length $T_m = T / 2^{m-1}$. For instance, a 12-layer encoder split into three 4-layer blocks (written B4-4-4) runs its first four layers at full length $T$, its middle four layers at half length $T/2$, and its final four layers at quarter length $T/4$.

Recall a basic property of attention: the output sequence always has the exact same length as the queries $Q$, regardless of how many keys $K$ and values $V$ those queries inspect. So at the very first layer of a new block, Funnel-Transformer runs stride-2 mean pooling on the previous block's hidden states $h$ to create a half-length sequence $h' = \text{Pool}(h)$. It feeds that short sequence $h'$ as the queries $Q$ and as the residual stream base, while feeding the unpooled sequence $h$ as keys $K$ and values $V$. That single transition layer turns downsampling into a learned, content-weighted compression step.

There is one small catch with the special sentence-summary token [CLS] at position 0. If you ran stride-2 pooling across the whole tensor blindly, [CLS] would get averaged with the first content word of the sentence at Block 2, and then averaged with the first three words at Block 3. To keep the global summary clean, Funnel-Transformer slices off [CLS] before pooling the content tokens and prepends it back onto $h'$ intact (Separate-CLS).

3. Second pooled query $q_2$: Suppose $q_2$ attends asymmetrically to tokens 3 and 4 with weights $\alpha^{(2)} = [0,\; 0,\; \frac{1}{4},\; \frac{3}{4}]$ over unpooled values $v_3 = 10$ and $v_4 = 14$.

$$h' = \text{Pool}(h), \qquad h \leftarrow \text{LayerNorm}\Bigl(h' + \text{Attn}\bigl(Q=h',\; K=h,\; V=h\bigr)\Bigr)$$
Only the boundary transition layer mixes shapes $(T/2) \times T$. Every interior layer after that runs standard self-attention where $Q, K, V$ all have length $T/2$—cutting the $T_m \times T_m$ attention matrix by $4\times$ and the per-token FFN work by $2\times$.

Notice why every piece of that update rule has to be there. Using the pooled state $h'$ as the residual base is not optional: the attention output has length $T/2$, so you cannot add it to the unpooled length-$T$ tensor $h$, and dropping the residual skip connection across block transitions would starve early layers of gradient signal. Furthermore, because each step from index $i$ to $i+1$ in Block 2 now spans two original words instead of one, Funnel-Transformer doubles the relative positional encoding stride at each block boundary so distance $+1$ in Block 2 aligns with distance $+2$ in Block 1.

3. Recovering Individual Tokens: Bridge Upsampling & FLOP Reinvestment

If your only goal is sequence classification (like sentiment analysis or GLUE sentence pairs), you never need the individual token slots back—you just read the final [CLS] vector at the end of Block 3. What if you are pretraining with Masked Language Modeling or extracting answer spans on SQuAD, where you need a distinct vector at every single token $1 \dots T$?

Image segmentation networks like U-Net solve this with a heavy mirror-image decoder that upsamples step-by-step after every block. Funnel-Transformer takes a much cheaper shortcut called Bridge Upsampling. It takes the final compressed sequence $h^{(M)}$ (say, at length $T/4$) and simply repeats each vector $2^{M-1} = 4$ times to stretch it back to length $T$ ($h^{\text{up}}$).

Of course, repeating each compressed vector four times makes every group of four adjacent tokens identical copies of one another. To give each position its individual word identity back, Funnel-Transformer adds a long residual bridge directly from the uncompressed end of Block 1 ($h^{(1)}$), and passes the sum through just 2 standard full-length Transformer decoder layers:

$$\forall i \in \{1,\dots,T\}:\quad h^{\text{up}}_i = h^{(M)}_{\lfloor i / 2^{M-1} \rfloor}, \qquad g = h^{(1)} + h^{\text{up}}$$
Once pretraining finishes, you can throw the 2-layer decoder away completely for classification fine-tuning—or keep it for token-level tagging.

Tracing Bridge Upsampling on our 4-token phrase ($M = 3$ blocks $\implies$ repeat factor $2^{3-1} = 4$):

Suppose our 4-token phrase passes through a 3-block encoder ($T_1 = 4 \to T_2 = 2 \to T_3 = 1$):
• Uncompressed Block-1 output $h^{(1)}$ (length 4, distinct local token values): $h^{(1)} = [1,\; 3,\; 5,\; 7]$.
• Final compressed Block-3 output $h^{(3)}$ (length 1 global context summary): $h^{(3)} = [10]$.
• Step 1 (Repeat $h^{(3)}$ four times to match length 4): $h^{\text{up}} = [10,\; 10,\; 10,\; 10]$. All four slots are identical copies.
• Step 2 (Add the Block-1 bridge $g = h^{(1)} + h^{\text{up}}$): The first three tokens become $g_1 = 1 + 10 = 11$, $g_2 = 3 + 10 = 13$, and $g_3 = 5 + 10 = 15$.

This sequence compression unlocks a powerful trade-off that Dai et al. call FLOP reinvestment. Because layers running at length $T/2$ and $T/4$ cost half or a quarter as much compute as a full-length layer, you can either pocket the savings to run a 12-layer model $\sim 42\%$ faster (B4-4-4), or spend the saved FLOPs on stacking deeper blocks (like an 18-layer B6-6-6 encoder) that still finishes faster than a flat 12-layer BERT while beating it on accuracy.

4. Where Funnel-Transformer Breaks & Hands-On Practice

If Funnel-Transformer saves so much compute on BERT-style encoders, why don't autoregressive GPT decoders use stride-2 pooling in the middle of the network? Because in next-token generation, position $2i-1$ is forbidden from seeing future token $2i$. Averaging token pair $(2i-1, 2i)$ and later upsampling it back to both slots leaks token $2i$ backward into position $2i-1$, breaking the causal mask. Funnel pooling is built for bidirectional encoders that read the full input prompt at once.

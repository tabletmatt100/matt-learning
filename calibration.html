Probability Calibration: When 80% Actually Means 80%

TL;DR

  • A classifier is calibrated if its predicted probabilities match empirical frequencies: out of all samples given score $0.80$, about $80\%$ actually belong to the positive class.
  • Ranking metrics like ROC-AUC and PR-AUC only care about order. A model can have a $0.95$ ROC-AUC while its probabilities are wildly wrong.
  • Different model families fail in opposite directions: deep neural networks tend to be overconfident (pushing scores toward $0$ and $1$), whereas random forests and shallow boosted trees often push scores away from the extremes (underconfident).
  • Measure calibration visually with a reliability diagram and numerically with Expected Calibration Error (ECE), Brier score, and log loss.
  • Fix miscalibration on a held-out validation set (never the training set) using Platt scaling, temperature scaling, or isotonic regression.

1. Ranking is not probability

Suppose a weather app predicts a $70\%$ chance of rain on $100$ different days, and it rains on $71$ of them. That forecast is calibrated. Formally, a binary classifier outputting score $\hat{p} \in [0, 1]$ for true label $Y \in \{0, 1\}$ is calibrated if:

$$P(Y = 1 \mid \hat{p} = p) = p \quad \text{for all } p \in [0, 1]$$
Among all examples where the model outputs $p$, the true fraction of positives is $p$.

You do not always need calibrated probabilities. If your only job is to send the top $50$ highest-scoring leads to a sales team each morning, only the ranking matters. Any strictly increasing transformation of the scores leaves the top $50$ unchanged.

Calibration becomes mandatory the moment a downstream calculation treats $\hat{p}$ as a literal probability:

  • Expected cost decisions: Flagging a transaction when expected loss $\hat{p} \times \text{\$Amount} > \text{\$ReviewFee}$. If $\hat{p}$ is inflated $3\times$, you review $3\times$ too many low-risk transactions.
  • Model chaining and ensembles: Multiplying or averaging probabilities across different models (say, combining an image classifier with a patient history model via Bayes' rule).
  • Human-facing risk scores: Telling a physician that a tumor has a $15\%$ malignancy risk, or quoting an insurance premium from predicted claim probability.
Sharpness vs. Calibration

A lazy model that predicts the base rate $\pi = 0.20$ for every single row is $100\%$ calibrated: out of everyone given $0.20$, exactly $20\%$ are positive. It is also useless because it has zero sharpness (discrimination). Good probabilistic models need both: high discrimination to separate positives from negatives, and calibration so the numbers tell the truth.

Model A predicts $0.20$ for all negative examples and $0.30$ for all positive examples. Model B predicts the base rate $0.50$ for every example on a balanced dataset. Which statement is true?

2. Reliability diagrams, ECE, and Brier score

To check whether a model is calibrated on a test set of $N$ examples, sort the predictions into $M$ bins (for instance, $[0.0, 0.2], (0.2, 0.4], \dots, (0.8, 1.0]$). Inside each bin $B_m$, compute two averages:

  • Mean predicted confidence $\text{conf}(B_m)$: the average of $\hat{p}_i$ for rows in bin $B_m$.
  • Empirical fraction of positives $\text{acc}(B_m)$: the fraction of rows in bin $B_m$ where $y_i = 1$.

Plotting $\text{acc}(B_m)$ on the y-axis against $\text{conf}(B_m)$ on the x-axis produces a reliability diagram (also called a calibration curve). A calibrated model hugs the diagonal $y = x$.

$$\text{ECE} = \sum_{m=1}^{M} \frac{|B_m|}{N} \,\big|\text{acc}(B_m) - \text{conf}(B_m)\big|, \qquad \text{Brier} = \frac{1}{N}\sum_{i=1}^{N} (\hat{p}_i - y_i)^2$$
ECE is the weighted average vertical gap from the diagonal. Brier score is the mean squared error of the probabilities.

Worked example ($N = 100$ test patients across $M = 3$ bins):

Bin $B_m$ Count $|B_m|$ Mean Predicted $\text{conf}(B_m)$ Actual Positives Observed Rate $\text{acc}(B_m)$ Gap $|\text{acc} - \text{conf}|$
Low $[0.0, 0.33]$ 50 0.10 5 $5/50 = 0.10$ $|0.10 - 0.10| = 0.00$
Mid $(0.33, 0.66]$ 30 0.50 12 $12/30 = 0.40$ $|0.40 - 0.50| = 0.10$
High $(0.66, 1.0]$ 20 0.90 13 $13/20 = 0.65$ $|0.65 - 0.90| = 0.25$

Step 1 (Expected Positives vs Actual): Summing predicted probabilities gives $50(0.10) + 30(0.50) + 20(0.90) = 5 + 15 + 18 = 38$ expected cases, whereas only $5 + 12 + 13 = 30$ occurred. The high bin is noticeably overconfident ($0.90$ predicted vs $0.65$ actual).

Step 2 (ECE): Weight each bin's gap by its share of the $100$ patients: $$\text{ECE} = \frac{50}{100}(0.00) + \frac{30}{100}(0.10) + \frac{20}{100}(0.25) = 0.00 + 0.03 + 0.05 = 0.080$$ On average, the model's probability estimate is off by $8.0$ percentage points.

While ECE measures only calibration gap, the Brier score and log loss are proper scoring rules: they penalize both poor calibration and poor discrimination at the same time.

Math deeper look: Murphy decomposition of the Brier score

Why can a constant-base-rate predictor have $\text{ECE} = 0$ but a mediocre Brier score? Murphy (1973) showed that across bins with overall base rate $\bar{y} = \frac{1}{N}\sum y_i$, the Brier score splits into three pieces:

$$\text{Brier} = \underbrace{\frac{1}{N}\sum_{m=1}^{M} |B_m|\big(\text{conf}(B_m) - \text{acc}(B_m)\big)^2}_{\text{Reliability (calibration error, lower is better)}} - \underbrace{\frac{1}{N}\sum_{m=1}^{M} |B_m|\big(\text{acc}(B_m) - \bar{y}\big)^2}_{\text{Resolution (sharpness, higher is better)}} + \underbrace{\bar{y}(1 - \bar{y})}_{\text{Uncertainty}}$$

Reliability measures how close the bins sit to the diagonal (0 is best). Resolution rewards bins whose true rates $\text{acc}(B_m)$ spread far away from the dataset base rate $\bar{y}$. Uncertainty $\bar{y}(1-\bar{y})$ depends only on the dataset balance. Calibration post-processing shrinks the Reliability penalty without changing Resolution.

3. Why models go out of calibration

Different algorithms distort probabilities in characteristic ways. You can spot the distortion directly from the shape of the reliability diagram:

Model / Training Setup Typical Distortion Curve Shape vs Diagonal Why It Happens
Logistic Regression (well-specified, natural prior) Well calibrated Directly on diagonal $y = x$ Directly minimizes log loss with low capacity.
Modern Deep Neural Nets, Naive Bayes Overconfident (pushed toward $0$ and $1$) Transposed S-curve: above diagonal for $p < 0.5$, below for $p > 0.5$ High-capacity nets overfit NLL on easy training examples by magnifying logits (Guo et al., 2017); Naive Bayes double-counts correlated features.
Random Forests, bagged trees, SVMs Underconfident (pushed toward $0.5$) S-curve: below diagonal for $p < 0.5$, above for $p > 0.5$ Averaging predictions across noisy trees makes $0.0$ or $1.0$ nearly impossible; all trees would have to agree unanimously.
Class weights / Oversampling (50:50 train, rare test) Prior-shifted (inflated everywhere) Bowed far below the diagonal across the whole range Model learns odds multiplied by the weight or sampling ratio $w_1 / w_0$.

Notice how the two S-curves work. Take an overconfident model: when the true risk is $0.70$, it boasts $0.92$ (plotting at $x=0.92, y=0.70$, below the diagonal). When the true risk is $0.30$, it boasts $0.08$ (plotting at $x=0.08, y=0.30$, above the diagonal). An underconfident random forest does the exact reverse: it hedges toward $0.5$, predicting $0.65$ when the truth is $0.85$ (above the diagonal on the right) and $0.35$ when the truth is $0.15$ (below the diagonal on the left).

4. Three fixes: Platt, temperature, and isotonic

Post-hoc calibration takes a trained model's raw logits $z_i$ (or raw scores $s_i$) and fits a lightweight mapping on a held-out calibration set $(X_{\text{cal}}, y_{\text{cal}})$ that has the real production class balance:

$$\text{Temperature Scaling: } \hat{p}_i = \sigma\!\left(\frac{z_i}{T}\right) \qquad \text{Platt Scaling: } \hat{p}_i = \sigma(a z_i + b)$$
where $\sigma(u) = \frac{1}{1 + e^{-u}}$ is the sigmoid function. Fit $T$ or $(a, b)$ by minimizing log loss on held-out validation data.
  1. Temperature scaling ($1$ parameter, $T > 0$): Divide the network's logits by scalar $T$ before softmax or sigmoid. Setting $T > 1$ softens an overconfident deep net toward $0.5$; $T < 1$ sharpens an underconfident model. Because it has no intercept $b$, it cannot fix a class-balance shift, and in multiclass settings it never changes the top-1 predicted class ($\arg\max_k z_k / T$).
  2. Platt scaling ($2$ parameters, slope $a$ and intercept $b$): A 1D logistic regression on top of the model's log-odds or raw score. Slope $a$ fixes over/underconfidence (just like $1/T$), while intercept $b$ absorbs any prior shift from class weights or undersampling. Best default when your calibration set has fewer than $1{,}000$ examples.
  3. Isotonic regression (non-parametric step function): Fits a general piecewise-constant non-decreasing curve $\hat{p}_i = f(s_i)$ using the Pool Adjacent Violators Algorithm (PAVA). Can fix asymmetric distortions that aren't S-shaped, but overfits badly on small calibration sets (turns into a jagged staircase). Use only when you have $>1{,}000$ calibration examples.

Worked arithmetic: fixing an overconfident logit with temperature and Platt scaling

Suppose a deep model scores a borderline sample with raw logit $z = +2.20$.

Unadjusted output ($T = 1$): $\hat{p}_{\text{raw}} = \sigma(2.20) = \frac{1}{1 + e^{-2.20}} = \frac{1}{1 + 0.1108} \approx 0.900$.

With Temperature scaling ($T = 2.0$ fitted on validation): $$\hat{p}_{\text{temp}} = \sigma\!\left(\frac{2.20}{2.0}\right) = \sigma(1.10) = \frac{1}{1 + e^{-1.10}} = \frac{1}{1 + 0.3329} \approx 0.750$$

With Platt scaling ($a = 0.5, b = -0.40$ to also correct a prior shift): $$\hat{p}_{\text{platt}} = \sigma(0.5 \times 2.20 - 0.40) = \sigma(0.70) = \frac{1}{1 + e^{-0.70}} = \frac{1}{1 + 0.4966} \approx 0.668$$

How Isotonic Regression Works: PAVA Step-by-Step

Suppose $5$ samples are sorted by raw model score $s_1 < s_2 < s_3 < s_4 < s_5$, with true labels $y = [0, 1, 0, 1, 1]$. Because $y_2 = 1 > y_3 = 0$, the sequence violates monotonicity. Step through the Pool Adjacent Violators Algorithm (PAVA) to see how it pools neighboring blocks into a non-decreasing step function.

Code: Platt scaling, Isotonic regression, and Temperature scaling in Python 
import numpy as np
from sklearn.calibration import CalibratedClassifierCV, calibration_curve
from sklearn.frozen import FrozenEstimator
from sklearn.metrics import brier_score_loss, log_loss, roc_auc_score
from scipy.optimize import minimize
from scipy.special import expit

# 1. Fit Platt ("sigmoid") or Isotonic on an untouched validation set (sklearn >= 1.6)
platt_model = CalibratedClassifierCV(FrozenEstimator(clf), method="sigmoid")
platt_model.fit(X_val, y_val)
p_test = platt_model.predict_proba(X_test)[:, 1]

print("Brier:", brier_score_loss(y_test, p_test))
print("LogLoss:", log_loss(y_test, p_test))
print("ROC-AUC:", roc_auc_score(y_test, p_test))

# 2. Minimal 1-parameter Temperature Scaling on raw binary logits z_val
def fit_temperature(z_val, y_val):
    def nll(log_T):
        T = np.exp(log_T[0])
        p = np.clip(expit(z_val / T), 1e-12, 1 - 1e-12)
        return -np.mean(y_val * np.log(p) + (1 - y_val) * np.log(1 - p))
    res = minimize(nll, x0=[0.0], method="BFGS")
    return float(np.exp(res.x[0]))

Never fit the calibrator on the same rows used to train clf. Because the base model already has lower training loss than validation loss, fitting a calibrator on training predictions teaches it to trust the base model's overconfidence.

Feature Engineering: Turning Raw Columns Into Signals Models Can Actually Split On

TL;DR

  • Match the feature to the model's blind spot: Linear models and distance-based models need scaling, log transforms for heavy skew, and explicit $\sin/\cos$ cyclical features. Decision trees (XGBoost / LightGBM) are immune to monotonic scaling, so feeding them $2x$ or $\ln(x)$ changes nothing—what trees crave are ratios and differences ($x_1 / x_2$, $x_1 - x_2$) that avoid clumsy staircase splits.
  • Encode categories without inventing fake order or leaking the target: One-hot encoding works for low-cardinality categories ($K \le 15$), while target encoding compresses high-cardinality IDs (like 5,000 zip codes) into a single smoothed prior—provided you compute it out-of-fold and never include a row's own label $y_i$.
  • Every stateful transform must be fit on training folds only: Computing a mean $\mu$, standard deviation $\sigma$, or target encoding map across the full dataset before splitting causes data leakage.

1. Why Trees Need Ratios While Linear Models Need Scaling

Running Scenario: Loan Default Risk

You are predicting whether a loan applicant will default ($y \in \{0, 1\}$) from two raw columns: Annual Debt ($x_1$) and Annual Income ($x_2$), plus their Zip Code and Application Hour ($h \in [0, 23]$).

Quick Prediction: Tree Blind Spots

Can a Decision Tree Split Cleanly on $x_1 / x_2 > 0.5$?

Suppose applicants default whenever their Debt-to-Income ratio exceeds $0.5$ ($x_1 > 0.5\,x_2$, a diagonal line across the Debt vs. Income plot). You train a decision tree on raw Debt ($x_1$) and raw Income ($x_2$). If you now add a third column $x_3 = \ln(x_2)$, vs. adding $x_4 = x_1 / x_2$, which engineered column helps the tree?

A decision tree only makes axis-aligned splits ($x_1 > c$ or $x_2 > c$, vertical or horizontal cuts). To approximate a diagonal boundary like $\text{Debt} / \text{Income} > 0.5$, a tree on raw $(x_1, x_2)$ has to carve a jagged staircase of many splits—and fails completely whenever income rises outside the training range.

Worked trace (3 applicants with identical 50% debt-to-income ratio):

• Applicant A: Debt $x_1 = 20\text{k}$, Income $x_2 = 40\text{k} \implies \text{Ratio } r = \frac{20}{40} = \mathbf{0.50}$.
• Applicant B: Debt $x_1 = 40\text{k}$, Income $x_2 = 80\text{k} \implies \text{Ratio } r = \frac{40}{80} = \mathbf{0.50}$.
• Applicant C: Debt $x_1 = 30\text{k}$, Income $x_2 = 100\text{k} \implies \text{Ratio } r = \frac{30}{100} = \mathbf{0.30}$.
On raw $x_1$ alone, Applicant C ($30\text{k}$ debt) sits between A ($20\text{k}$) and B ($40\text{k}$), so no single threshold on Debt can separate $\{A, B\}$ from $C$. Once you engineer the interaction feature $r = x_1 / x_2$, a single split at $r \ge 0.50$ separates them cleanly in 1 node.

2. Numerical & Cyclical Transforms

While trees ignore monotonic rescaling, linear models ($\hat{y} = w_1 x_1 + w_2 x_2 + b$), neural networks, and k-NN depend directly on feature distances and slopes:

  • Z-Score Standardization ($z = \frac{x - \mu}{\sigma}$): If Income is measured in dollars ($40{,}000$) and Age in years ($40$), unscaled L2 regularization and gradient descent treat a $1$-unit change in Income and Age equally. Subtracting the training mean $\mu_{\text{train}}$ and dividing by $\sigma_{\text{train}}$ puts every feature in standard-deviation units (mean $0$, variance $1$).
  • Log Transform ($\tilde{x} = \ln(1 + x)$): Income and transaction counts have heavy right tails ($10\text{k}$, $100\text{k}$, $10\text{M}$). Taking $\log_{10}(x)$ turns multiplicative $10\times$ jumps into equal $+1$ additive steps ($4, 5, 7$) so a single millionaire row does not hijack a linear regression line.
  • Cyclical Encoding ($\sin / \cos$): If you feed raw Hour $h \in \{0, 1, \dots, 23\}$ into a model, 11:00 PM ($h = 23$) and Midnight ($h = 0$) look $23$ hours apart—the maximum possible distance! Mapping $h$ onto a unit circle fixes the seam:
$$h_{\sin} = \sin\!\left(\frac{2\pi h}{24}\right), \qquad h_{\cos} = \cos\!\left(\frac{2\pi h}{24}\right)$$
You always need both $\sin$ and $\cos$: $\sin$ alone gives the same value for 6:00 AM ($+1$) and... wait, $\sin$ gives $0$ at both 0:00 and 12:00 Noon! Adding $\cos$ ($+1$ at 0:00, $-1$ at 12:00) makes every hour unique.

3. Categorical Encoding & The Target Leakage Trap

How do you turn a string column like zip_code into numbers?

  • Low cardinality ($K \le 15$, e.g., payment_type): Use One-Hot Encoding ($K$ binary $0/1$ columns). Avoid arbitrary integer IDs ($1, 2, 3$) in linear models because that claims Category 3 is "three times" Category 1.
  • High cardinality ($K = 5{,}000$, e.g., zip_code or merchant_id): One-hot encoding explodes into $5{,}000$ sparse columns. Instead, use Smoothed Target Encoding: replace each category $c$ with a blend of its training target rate $\bar{y}_c$ and the global prior $\bar{y}_{\text{global}}$:
$$\hat{y}_c = \frac{n_c \bar{y}_c + m \bar{y}_{\text{global}}}{n_c + m} = \frac{\text{positives}_c + m \bar{y}_{\text{global}}}{n_c + m}$$
Click any symbol: $\hat{y}_c$ = encoded feature value, $n_c$ = training count in category $c$, $\bar{y}_c$ = category positive rate, $m$ = smoothing weight (pseudo-count), $\bar{y}_{\text{global}}$ = overall base rate.

Mental-math trace (why smoothing $m$ and out-of-fold computation matter):

Suppose the overall default rate is $\bar{y}_{\text{global}} = 0.20$ ($20\%$) and we set smoothing weight $m = 10$.
• Zip A (tiny sample: $n_A = 1$ loan, and it defaulted, so $\text{positives}_A = 1$, raw $\bar{y}_A = 100\%$):
Naive target encoding gives $1.00$ (memorizing a 1-row fluke!). With smoothing $m = 10$:
$$\hat{y}_A = \frac{1 + 10(0.20)}{1 + 10} = \frac{1 + 2}{11} = \frac{3}{11} \approx \mathbf{0.273}$$ Because $n_A = 1 \ll m = 10$, the estimate shrinks heavily toward the $0.20$ global prior.
• Zip B (large sample: $n_B = 90$ loans, $45$ defaulted, raw $\bar{y}_B = 50\%$):
$$\hat{y}_B = \frac{45 + 10(0.20)}{90 + 10} = \frac{45 + 2}{100} = \mathbf{0.470}$$ Because $n_B = 90 \gg m = 10$, the data dominates and the encoded value stays close to $0.50$.

4. Cheat Sheet: Which Model Needs Which Feature?

Transform Linear / Logistic & MLP Tree Ensembles (XGBoost / RF) Leakage Risk?
Z-Score / Min-Max Scaling Essential (balances gradient steps & L1/L2 penalties) Zero effect (trees split on rank order only) Low (still fit $\mu, \sigma$ on train only)
Log1p ($\ln(1+x)$) High impact (tames right-skewed outliers) Zero effect on single column (monotonic) None (stateless row operation)
Ratios & Differences ($x_1/x_2$) High impact (linear models cannot divide inputs) Huge impact (replaces multi-split staircases) None (stateless row operation)
Cyclical $\sin/\cos$ Essential (connects $23:00$ to $00:00$) Helpful (saves 2 splits to wrap midnight) None (known period $P = 24$ or $7$)
Smoothed Target Encoding High impact (compresses $5{,}000$ levels into 1 slope) High impact (avoids deep one-hot trees) Extreme (must use out-of-fold + smoothing $m$)
